- 범위: 발표 중 **툴 화면·노드 방식**에 관한 내용만 추림. 자막 + 영상 프레임 직접 확인 기준.

발표에서 다루는 툴은 두 개다: 노드 방식 자동화 툴 **QAMate AutoFlow**, 웹 기반 테스트 케이스 관리 툴 **Case Manager**.

## 1. QAMate AutoFlow (노드 방식 자동화 툴)

- **한 줄 정의(슬라이드 문구)**: "제공되는 기능 노드를 조합하여, 순서대로 자동 실행시키는 도구"
- **개발**: 넥슨 운영개발실. 앞서 상용 솔루션과 QA 자체 개발은 실패했다고 함.
- **설계 방향**: QA 누구나 쓸 수 있는 쉬운 사용성이 기본. 필요하면 커스텀 노드를 추가 개발해서 사용.
- **방식**: 게임 엔진에 연동하지 않음. 게임 창을 잡아 마우스·키 입력을 보내는 외부 매크로 방식 → 장르·엔진이 다른 여러 게임에 공통 적용 가능.

> 화면 캡처 생략 (AutoFlow 에디터) — 저작권 때문에 레포에 넣지 않음. 출처 영상 참고

### 화면 구성 (v0.9.4 스크린샷 기준)

| 영역 | 내용 |
|---|---|
| 상단 툴바 | 클라이언트 선택 드롭다운, 캡션(창 제목, 예: `SM`), 윈도우 클래스, **실행(F5)** 버튼, 줌(100%) |
| 좌측 팔레트 | 검색 필터 + 탭 3개: **Step / Value / Custom**. 노드를 끌어다 놓는 방식 |
| 캔버스 | 열린 파일 이름 표시(`강화반복_1223.json`, 스크립트는 **JSON 저장**), 수정 시 `(수정됨)` 표시 |
| 실행 중 표시 | 현재 실행 중인 노드를 **초록색으로 강조** (나머지는 빨간색) |

### 확인된 노드 종류

| 노드 | 입력·출력 핀 / 속성 |
|---|---|
| **Start** | 출력: 윈도우핸들 |
| **End** | 입력: 반환값 |
| **FindWindow** | 클라이언트 선택. 출력: 윈도우핸들, **실패** |
| **SelectWindow** | 입력: 윈도우핸들 |
| **MouseClick** | 클릭 위치 좌표(예: `1070,260`), 이벤트(Right Click 등) |
| **ClickUI** | 버튼 이미지 지정(예: "초기화", "Ok") → 출력: UI위치, **실패**. 이미지 인식 클릭으로 보임(추정) |
| **KeyPress** | 키(예: F11, Enter) |
| **TextInput** | 텍스트 입력, 클립보드 사용 체크박스 |
| **Repeat** | 반복 횟수(예: 99, 10). 출력: 반복 흐름, **인덱스** |
| **Command** | 외부 명령 실행(예: `four_finger.bat`) |
| 주문서(사용자 정의) | Param0, 반환값, 파라미터 추가(+) 버튼. Custom 탭의 서브스크립트/함수 노드로 보임(추정) |
| 값 노드(파란색) | 출력: 텍스트, 문자열 목록. Value 탭 노드로 보임 |

> 화면 캡처 생략 (강화 반복 노드 그래프) — 저작권 때문에 레포에 넣지 않음. 출처 영상 참고

### 노드 연결 방식의 특징

- 실행 흐름 선과 데이터 선이 분리됨. 데이터 핀은 왼쪽 입력, 오른쪽 출력.
- **연결선마다 다음 노드까지의 대기 시간이 붙음** (`0.5 sec`, `1 sec`, `3 sec`). Delay 노드를 따로 두지 않고 엣지 속성으로 처리.
- FindWindow, ClickUI 등은 실패용 출력이 따로 있어 분기 가능.
- 노드 위의 작은 `EX` 태그는 의미 설명 없음.

### 활용 사례 (툴 설계 참고)

- 창고 열기·닫기 수백 회 반복으로 크래시 재현. 스크립트가 반복을 맡는 동안 사람은 조건을 바꿔 가며 테스트.
- 확률 검증: 상자 개봉 1만 회 이상, 장비 강화 1만 회 이상 → **로그 추출 후 확률만 검토**. 사람이 하면 약 80시간(영업일 10일).
- 던전 반복 클리어 후 보상 로그 집계, 약 5시간 걸리는 합성 반복, 덤프 추출 위임.
- 로그가 없는 영역은 **OCR로 화면 문자를 읽어 엑셀에 기록하는 기능**을 만들어 사용.
- 게임 간 동작이 비슷한 영역은 "공통 영역"으로 정해 스크립트 구조 표준화 → 게임별로 이식.
- 향후 계획(슬라이드): 교육·사례 공유, 자동화 영역 확대, **작성 편의 개선 & 복잡한 작업 수행 지원** 등 도구 기능 강화.

## 2. Case Manager (테스트 케이스 통합 관리 툴, 웹)

> 화면 캡처 생략 (Case Manager 화면) — 저작권 때문에 레포에 넣지 않음. 출처 영상 참고

- **화면**: 브라우저 웹앱. 왼쪽 **폴더 트리**(카테고리 계층, 항목마다 편집·삭제 아이콘), 오른쪽 테스트 케이스 **표**(열 내용은 블러 처리).
- **기능**
  - 게임별로 엑셀/SharePoint 에 따로 관리하던 테스트 케이스를 통합. 공통 영역(예: 쿠폰)은 같은 케이스 공유, 변경 시 실시간 갱신.
  - 검색으로 과거 중요 결함과 그 결함을 일으킨 케이스 조회. **다른 게임의 유사 영역 사례도 함께 검색**.
  - 케이스마다 진행 상태·테스트한 사람 표시, 결함이 자주 나는 영역을 목록으로 확인.
- **설계 포인트**
  - **추상화**: "A를 준비하고 B 화면, C 단계에서 D를 수행하면 Y가 나오는가" 같은 절차 대신, "이 영역도 함께 테스트해 보세요", "이런 조건에서 결함이 많이 발생했어요" 같은 짧은 문장으로 작성.
  - **추천 기능(계획)**: 케이스 작성 시 해당 영역의 과거 중요 결함을 노출. 너무 많이 노출하면 혼선 → 영역별 카테고리·태그·유용성 평가로 매칭 정확도 향상. 재발 여부 체크 값으로 가치 높은 케이스를 먼저 노출할 예정.

## 한계

- 툴 화면은 몇 초씩 지나가는 저해상도(720p) 영상이라 핀 이름 일부는 흐릿함.
- 노드 내부 동작, 데이터 타입, 조건 분기 노드 유무 같은 구조 설명은 발표에 없음.
- Case Manager 는 화면 대부분이 블러 처리되어 레이아웃만 확인됨.
