## 1. 노드 에디터·실행·디버깅

### Unreal Engine Blueprint
- 실행 핀·와이어는 흰색, 데이터 핀은 타입별 색. exec 핀이 없는 순수 노드는 필요할 때만 계산
- 디버거: 노드 브레이크포인트, Step Into/Over/Out, Call Stack, 실행된 노드를 쌓는 Execution Trace
- 핀 우클릭 "Watch this value", 일시정지 중 핀에 마우스를 올리면 값 툴팁
- Collapse Nodes / Collapse to Function / Macro 로 묶기, Comment·Reroute
- 단점: 바이너리 .uasset 저장이라 diff·병합 불가

### ComfyUI
- 입력 해시로 노드 출력을 캐시하고, 바뀐 노드와 그 아래쪽만 다시 실행
- 부분 실행: 출력 노드를 골라 그 가지만 실행
- 서브그래프: 중첩 가능, 상단에 깊이 표시, 라이브러리에 블루프린트로 등록
- 공식 MCP(베타): `search_nodes`, `get_node`, `validate_workflow`, `run_workflow`, `watch_job`, `fetch_outputs`
- 단점: UI 포맷과 API 포맷이 달라 서로 호환이 안 됨. litegraph 포크는 아카이브됨

### n8n
- **Pinned data**: 노드 출력을 고정·편집하고, 수동 실행에서 그 값으로 아래쪽을 진행
- **Executions**: 과거 실행을 열면 당시 노드별 입출력이 캔버스에 표시. 실패 실행은 "Debug in editor"로 재현
- 재시도를 "실행 당시 버전으로"와 "현재 버전으로" 중에서 고름
- AI Agent 노드(모델·메모리·도구를 서브노드로), MCP Client/Server 노드, 자연어 워크플로 빌더
- 단점: 연결을 노드 이름으로 참조(추정)하고, 좌표가 로직과 섞여 diff 잡음이 큼

### Node-RED
- Flow Debugger: 포트 단위 브레이크포인트, 대기 메시지 큐를 보고 메시지 단위로 step
- Subflow(묶음 → 새 노드), Link 노드(탭을 넘나드는 가상 와이어)
- 단점: 작은 수정에도 diff가 거대함. 일시정지해도 타이머는 계속 돎

### Blender Geometry Nodes / Houdini
- 노드마다 마지막 실행 시간을 표시하고, Frame에는 안쪽 합계를 표시
- 단일 값은 소켓 옆에 바로 표시하고, 큰 데이터는 Viewer 노드로 봄
- Houdini Performance Monitor: 자기 시간과 하위 포함 시간을 구분, CSV 내보내기

### Unity Visual Scripting
- 실행 전 정적 검사로 실패할 수 있는 노드는 노랑, 확실히 실패할 노드는 주황
- 실행 중인 노드는 파랑, 오류 노드는 빨강으로 표시하고 콘솔과 연결

### 웹 노드 에디터 라이브러리
| 라이브러리 | 특징 | 라이선스 |
|---|---|---|
| React Flow (xyflow) | 생태계가 가장 큼. 노드가 곧 React 컴포넌트. 대형 그래프는 화면 밖을 그리지 않는 설정이 필요(약 1000개 안팎이 한계라는 보고, 추정) | MIT |
| Rete.js v2 | dataflow와 controlflow를 섞는 엔진 내장. 렌더러 여러 개 | MIT (`rete-structures` 는 CC-BY-NC-SA) |
| litegraph.js | Canvas2D라 대형 그래프에 유리. UI 커스터마이징 비용이 큼. 원본은 정체, 포크는 아카이브 | MIT (추정) |
| BaklavaJS v2 | Vue 3, 타입 검사와 서브그래프 내장. 생태계 작음 | MIT |

## 2. GUI·게임 테스트 자동화

### SikuliX
- Pattern 객체에 `similar(0.x)`(최소 유사도)와 `targetOffset(dx,dy)`(클릭 지점)를 같이 저장
- **Matching Preview**: 유사도 슬라이더를 움직이면 현재 화면의 매칭 위치가 실시간으로 표시
- `find`(못 찾으면 예외) / `exists`(bool, 분기용) / `wait` 구분, Region으로 검색 범위 제한
- `onAppear` + `observe`로 예상하지 못한 팝업 처리 → "인터럽트 핸들러" 참고 모델
- 단점: 멀티스케일이 없어 해상도가 바뀌면 다시 캡처해야 함. 기본 OCR이 불안정

### Airtest + AirtestIDE (+ Poco)
- `Template` 에 `record_pos`(정규화 좌표)와 `resolution` 을 저장하고, 재생할 때 예상 위치 근처부터 탐색
- 클릭 지점은 키패드식 9분할(`target_pos=5` 가 중앙)
- 매칭 전략을 차례로 시도: 멀티스케일 템플릿 → 템플릿 → SIFT → BRISK. `rgb=True` 로 색까지 검증
- 스텝별 HTML 리포트(스크린샷 + 매칭 위치 + 화면 녹화)
- Poco: 엔진 SDK로 UI 트리를 읽음 → Kookabug에서는 "엔진 플러그인"이 이 역할
- 단점: 기본 타임아웃 20초라 실패가 늦게 드러남

### UiPath / Power Automate Desktop
- 다중 타깃팅: 셀렉터 → Computer Vision → 이미지 순서로 시도
- **Anchor Base**: 안정적인 주변 요소를 기준으로 상대 위치에서 찾음 (예: 골드 아이콘 오른쪽 숫자 OCR)
- 입력 방식을 옵션으로 두고 호환성을 공개: Hardware Events(포그라운드, 100%) / Simulate(백그라운드, 약 60%) / SendWindowMessages(약 80%)
- Object Repository: UI 요소 설명자를 라이브러리로 분리하고 버전 관리, 사용처 추적
- Retry Scope(동작 블록 + 조건 블록 + 횟수·간격)
- PAD: OCR 엔진(Windows OCR / Tesseract)과 이미지 매칭 알고리즘을 노드 속성으로 선택
- 단점: 여러 개가 매칭될 때의 규칙이 불명확해 반복 아이콘에서 오탐

### Robot Framework
- Python 라이브러리 키워드 위에 사용자 키워드를 쌓음 → **커스텀 노드 = 라이브러리 키워드, 서브그래프 = 사용자 키워드**
- 원본 결과(output.xml) 하나에서 log.html과 report.html을 생성. `rebot --merge` 로 여러 실행 결과를 합침
- 실패하면 자동 실행할 키워드 등록(실패 순간 스크린샷)
- `Wait Until Keyword Succeeds`, pabot 병렬 실행
- 단점: 텍스트 표 문법이라 비개발자가 어렵고 시각적 디버깅이 없음

### Playwright
- **Actionability**: 동작 전에 보이는지, 안정적인지(두 프레임 동안 같은 위치), 실제로 이벤트를 받는지, 활성 상태인지 확인하고 통과할 때까지 재시도
- 검증(`expect`)도 자동 재시도
- **Trace viewer**: 액션별 Before / Action(클릭 지점) / After 스냅샷, 타임라인, 실패 스텝으로 바로 이동
- 증거 정책 옵션: screenshot `only-on-failure`, video·trace `retain-on-failure | on-first-retry`
- codegen: 녹화하면서 검증 삽입, "커서 위치에 녹화 삽입"
- 단점: 기본 액션 타임아웃이 무제한

### Maestro
- 암묵 대기가 원칙. assertVisible이 폴링하다 맞으면 바로 진행
- `waitForAnimationToEnd`, `extendedWaitUntil`, `tapOn: retryTapIfNoChange`(탭 후 화면이 안 바뀌면 다시 탭)
- `runFlow` 로 서브플로 재사용, 사람이 읽는 YAML
- 단점: 느린 기기에서는 기본 대기만으로 부족하다는 비판

### AutoHotkey / PyAutoGUI / Appium 이미지 매칭
- AHK ImageSearch `*n`(색상 허용치), `*TransN`(투명색), 입력 경로 선택(`SendMode`, `ControlSend`)
- PyAutoGUI FAILSAFE(마우스를 모서리로 옮기면 중단) → **긴급 정지 핫키**
- Appium `fixImageTemplateScale`, `fixImageFindScreenshotDims`: 캡처 픽셀 좌표와 입력 좌표의 변환을 설정으로 명시

## 3. 외부 매크로 방식의 기술 이슈

| 이슈 | 내용 | 대응 |
|---|---|---|
| SendInput | 하드웨어 입력처럼 처리되어 DirectInput·Raw Input 게임에도 들어감. 포그라운드 창으로만 감. 무결성 수준이 높은 프로세스(관리자 권한 게임)에는 **조용히 실패** | 게임이 관리자 권한이면 러너도 관리자 권한. 입력 후 화면 변화로 실패 감지 |
| PostMessage | 백그라운드 전송 가능. 키 상태에 반영되지 않아 대부분의 게임에서 무효 | 노드 옵션으로만 제공 |
| 합성 입력 플래그 | SendInput 입력에는 OS가 `INJECTED` 플래그를 붙임. 안티치트가 감지 가능 | 우회 드라이버는 넣지 않음. 안티치트를 끈 QA 빌드나 엔진 플러그인 경로를 문서로 안내 |
| 포커스 | SetForegroundWindow가 OS 제약으로 실패할 수 있음 | "포커스 확보" 노드 + 입력 직전 검증 + 포커스를 빼앗기면 실패 사유로 기록 |
| 캡처 | BitBlt는 DirectX 창이 검게 나옴. DXGI는 모니터 단위이고 전체화면 전환 때 재생성 필요. WGC는 창 단위로 GPU 화면까지 캡처 | WGC → DXGI → PrintWindow → BitBlt 순서로 시도. 검은 프레임 감지. 테두리 없는 창 모드 권장 |
| DPI | Per-Monitor V2 DPI awareness는 프로세스 시작 때 설정해야 함 | 캡처와 입력을 물리 픽셀로 통일. 템플릿에 클라이언트 영역 기준 정규화 좌표 + 해상도 + DPI 저장 |
| 이미지 매칭 | 임계값, 스케일, 다중 매칭 | 스케일 범위 제한, 회색조 매칭 후 RGB 검증, 다중 매칭 선택 규칙 명시, 결과에 점수와 상위 후보 기록 |
| OCR | 엔진마다 장단점 | Windows OCR / Tesseract / PaddleOCR(게임 폰트에 강하다는 평가, 추정)을 교체 가능하게. 숫자 영역은 화이트리스트와 이진화 |
| CI·병렬 | 실제 GPU와 데스크톱 세션이 필요해서 진짜 헤드리스는 불가 | 자동 로그인된 전용 러너 기기. 기기·VM 1대당 게임 1개, 결과 병합 |

## 4. 플러그인 생태계

### VSCode Extensions
- `contributes` 선언에서 활성화 이벤트를 자동 생성해, 실제로 쓰일 때만 로드
- `engines.vscode` 로 호환 범위 선언
- Workspace Trust: 매니페스트에 신뢰하지 않는 워크스페이스 지원 여부를 선언. 선언이 없으면 Restricted Mode에서 비활성
- Extension Host 프로세스 분리. 확장이 UI를 느리게 만들 수 없음
- 마켓 서명·검증, 악성코드 스캔, 처음 보는 퍼블리셔 신뢰 확인
- `yo code` 스캐폴딩, F5로 개발 호스트 실행
- 단점: 권한 모델이 없음. 확장이 앱과 같은 권한으로 돎

### Obsidian
- 최소 매니페스트: `id`, `name`, `version`, `minAppVersion`, `description`, `author`, `isDesktopOnly`
- GitHub Release 자산 3개(`main.js`, `manifest.json`, `styles.css`)로 배포. 레지스트리는 목록만 관리
- `versions.json`: 플러그인 버전과 최소 앱 버전의 대응표
- Restricted Mode가 기본으로 켜져 있음
- 모든 버전 자동 심사와 공개 스코어카드(2026-05~)
- sample-plugin 템플릿, `.hotreload` 마커가 있는 플러그인만 자동 리로드
- 단점: 권한 제한과 샌드박스가 없고, 플러그인 간 의존성 선언이 없음

### ComfyUI custom nodes / Manager / Registry
Kookabug와 구조가 가장 비슷하다(Python 노드 + 웹 프런트).
- V3 스키마: `define_schema()` 가 입력·출력 타입을 선언하고, `execute()` 가 상태 없이 실행
- API 버전을 import 경로로 고정(`comfy_api.v0_0_2`)
- `WEB_DIRECTORY` 로 한 패키지에 Python 노드와 JS UI 확장을 같이 담음
- Registry: `pyproject.toml` 기반, 게시된 버전은 불변, 버전 단위 deprecate
- Manager: 워크플로에서 빠진 노드를 원클릭 설치, 환경 스냅샷과 복원, `use_uv`, 보안 레벨
- 금지 규칙: `eval`/`exec`, 런타임 pip 설치, 난독화
- **단점(핵심 교훈)**: 모든 플러그인이 환경 하나를 공유해서 플러그인 하나가 다른 플러그인을 깨뜨림. 사후 대책인 `pyisolate`(확장별 uv venv + JSON-RPC 자식 프로세스)는 아직 기본 기능이 아님

### n8n community nodes
- 선언형 노드 정의(`INodeTypeDescription`). 속성마다 조건부 노출을 정해 코드 없이 UI가 생김
- 노드 버전: 워크플로에 버전을 저장해 옛 워크플로는 옛 동작 유지
- CLI 하나로 `new` / `dev`(핫 리로드) / `lint` / `build` / `release`
- 검증 노드 기준: provenance 필수, 스캔 통과
- 단점: "외부 의존성 금지"는 QA·엔진 연동 플러그인에 너무 엄격

### Blender Extensions (4.2+)
- `blender_manifest.toml`: 매니페스트 자체의 `schema_version`, 앱 버전 범위, SPDX 라이선스, 플랫폼
- **권한 선언과 사유**: `permissions = {files="...", network="..."}` 를 설치 화면에 표시
- 런타임 pip 없이 플랫폼별 wheel을 번들
- 확장 폴더는 읽기 전용으로 취급하고, 사용자 데이터는 업그레이드 후에도 유지되는 별도 경로에 둠
- 정적 `index.json` 으로 서드파티 저장소 운영
- 단점: wheel이 실제로는 공유 네임스페이스라 같은 패키지의 다른 버전이 공존 불가(추정 포함). 권한은 선언일 뿐 강제되지 않음

### JupyterLab / pytest (짧게)
- JupyterLab: 토큰 기반 의존성 주입(`requires` / `provides`)으로 플러그인끼리 서비스를 주고받고 구현을 교체. pip 패키지 하나에 프런트 번들을 담는 prebuilt 확장
- pytest: entry points로 설치만 하면 발견. `-p no:name` 으로 특정 플러그인을 끄는 진단 방식. `conftest.py` 로 디렉터리 범위 로컬 플러그인

### uv
- Windows에서는 기본으로 캐시에서 hardlink 하므로, 캐시와 venv가 같은 드라이브면 플러그인별 venv를 여러 개 만들어도 비용이 작음
- 엄격한 해석기가 충돌을 설치 전에 찾아냄

### Kookabug 플러그인 구조 초안

```toml
# kookabug.toml
schema_version = "1"
id = "example-engine-sdk"     # 소문자·하이픈, 전역 고유
name = "Example Engine SDK Nodes"
version = "1.2.0"             # SemVer, 게시 후 불변
publisher = "example-org"
license = "MIT"
kookabug = ">=0.4,<1.0"       # 앱 호환 범위
node_api = "1"                # 노드 JSON 규격 버전
platforms = ["windows-x64"]

[python]
requires = ">=3.11,<3.13"
dependencies = ["requests>=2.31"]   # 범위 지정 권장, == 는 경고
isolation = "auto"                  # auto | shared | isolated

[permissions]                 # 사유를 설치 화면에 표시
network = "엔진 에디터 원격 제어 API 호출"
process = "게임 클라이언트 실행"

[contributes]
nodes = "nodes/"
ui = "ui/dist/index.js"       # 선택: UI 확장
settings = "settings.schema.json"

[trust]
untrusted = "limited"
```

```
plugins/<id>/
  kookabug.toml
  nodes/            # Python 노드
  ui/dist/          # 선택: 프런트 확장 번들
  schemas/*.json    # 빌드할 때 생성 → Python 없이 팔레트 표시
  wheels/           # 선택: 오프라인 배포
  .venv/            # isolated 일 때만
user-data/<id>/     # 업그레이드 후에도 유지
```

- **의존성 3단계**: shared(기본, uv로 전체 해석 + 설치 전 dry-run) → auto(충돌하면 그 플러그인만 격리로 전환) → isolated(전용 venv + 워커 프로세스 + stdio JSON-RPC). 노드 입출력이 이미 JSON이라 직렬화 비용이 작음
- **설치 흐름**: 목록 조회 → 호환성 필터 → 권한·퍼블리셔 확인 화면 → 해시 검증 → uv dry-run → 환경 스냅샷 → 설치 후 워커만 재시작
- **CLI**: `kookabug plugin new | dev | lint | build | publish`
- **진단 모드**: 플러그인을 하나씩 꺼 가며 원인을 찾음

## 5. 에이전트 연동·AI 자동화

### 앱이 외부 에이전트를 붙이는 방식
| 방식 | 장점 | 단점 |
|---|---|---|
| **ACP (Agent Client Protocol, Zed)** | JSON-RPC 표준. `session/new` 에 `mcpServers` 를 넣어 앱 MCP를 세션마다 주입(사용자 설정 파일을 안 건드림). 도구 호출에 종류·상태·diff가 붙어 패널 UI를 바로 그릴 수 있음. 승인 요청 선택지가 표준화(allow_once / allow_always / reject_once / reject_always). Claude는 `claude-agent-acp` 어댑터, Gemini는 `gemini --acp`. ACP Registry로 설치 | 권한 판단은 클라이언트 몫. 에이전트 권한과 앱 권한이 이원화 |
| JetBrains AI 패널 | ACP 에이전트를 레지스트리에서 설치하거나 커스텀 에이전트로 등록 | 자체 에이전트와 외부 에이전트의 기능 차이(추정) |
| Codex app-server | thread/turn/item 이벤트, 서버가 먼저 보내는 승인 요청, 스키마 자동 생성 | Codex 전용, 메서드 이름이 자주 바뀜 |
| PTY 터미널 임베드 | 어떤 CLI든 바로 지원, 에이전트 고유 기능 보존 | 구조화된 UI를 만들 수 없고 앱 쪽 권한 통제 불가 → 보조용 |
| Aside 브라우저 | 도구를 소수로 줄임(JS REPL + bash). 팝업·다운로드 같은 비동기 신호를 에이전트에 밀어줌. 화면은 압축 접근성 트리, 스크린샷은 폴백 | 사이드 패널 UX와 외부 에이전트 연동 방식은 공식 문서로 확인하지 못함 |

### MCP 서버 설계
- 도구는 API 1:1 래핑이 아니라 **워크플로 단위**로 만들고, 덤프보다 검색형으로 만듦 (`search_logs` 가 `read_logs` 보다 나음)
- `response_format`(간결 / 상세), 페이지네이션, 잘랐을 때 "더 좁게 검색하라" 안내, 오류 메시지에 올바른 입력 예시
- resource(앱이 고르는 컨텍스트, URI)와 tool(모델이 호출하는 행동)을 구분. `resources/subscribe` 로 실행 중 상태 푸시
- 도구 주석(readOnly / destructive / idempotent)은 힌트일 뿐 보안 경계가 아님
- 도구가 20~30개를 넘으면 선택 정확도가 떨어짐 → GitHub MCP의 `--toolsets` / `--dynamic-toolsets`, Anthropic Tool Search(`defer_loading`)
- 단독 CLI용 설정 파일 생성: Claude `.mcp.json`, Codex `.codex/config.toml`, Gemini `.gemini/settings.json`. 사용자 전역 설정은 몰래 고치지 않음

### 권한 UX
| 툴 | 흡수할 점 |
|---|---|
| Claude Code | deny → ask → allow 순서 평가. 범위는 user / project / local / managed(덮어쓸 수 없음). "다시 묻지 않기"를 고르면 규칙으로 저장. MCP 서버가 `requiresUserInteraction` 을 걸면 allow 규칙이 있어도 사람에게 물음 |
| Codex | "언제 묻는가"(approval_policy)와 "무엇이 가능한가"(sandbox_mode)를 분리. 프리셋 제공. 관리자 잠금 |
| VS Code / Cursor | 승인 범위를 한 번 / 세션 / 워크스페이스 / 항상 중에서 고름. MCP 서버 단위 → 도구 단위 체크박스. 거부가 항상 이김 |
| Gemini CLI | 서버별 includeTools / excludeTools, 겹치면 exclude가 이김. `trust: true` 는 너무 거침 |

### AI 기반 UI·게임 자동화
- **Midscene.js**: 계획형(`aiAct`)과 즉시형(`aiTap`, `aiQuery`, `aiAssert`)을 섞고 그 사이는 결정적 스크립트로 오케스트레이션. 계획을 캐시(read-write / read-only / write-only). 캐시가 실패하면 그 실행에서만 재계획. query·assert는 캐시하지 않음. 리포트에 캐시 적중 표시. 단점: canvas·WebGL은 위치 캐시가 불가해서 게임은 매번 AI 호출
- **Stagehand**: `observe` 로 행동을 미리 저장하고 LLM 없이 `act` 로 재생. 실패하면 원래 프롬프트를 한 번만 다시 추론
- **browser-use workflow-use**: 사람 시연을 변수화한 `.workflow.json` 으로 바꾸고, 재생에는 LLM을 쓰지 않음. 실패한 단계만 에이전트에게 넘김
- **Anthropic / OpenAI computer use**: 1280×720 수준으로 축소하고 좌표를 역변환. 작은 대상은 `zoom`. "매 단계 스크린샷으로 성공 판정". 화면 속 텍스트로 들어오는 프롬프트 인젝션 주의
- **UI-TARS**: 스크린샷만 받는 GUI 에이전트 모델(Apache 2.0), 자체 호스팅 가능

### 탐색 → 화면 지도
- **DroidBot / AutoDroid**: 탐색 결과를 상태 노드와 이벤트 엣지로 된 UI 전이 그래프로 남김. 상태마다 기능 요약표를 만들고, 실행할 때 지금 작업과 비슷한 항목만 주입
- **AppAgent**: 화면에 번호 태그를 덧그리고, 요소별 기능 설명을 문서로 축적
- **modl.ai**: 레벨을 구역으로 나눠 커버리지 히트맵, 크래시·오류 자동 보고(엔진 SDK 필요)
- **nunu.ai**: "튜토리얼을 플레이하라" 같은 자연어 테스트 계획을 엔진 통합 없이 비전으로 실행
- **연구**: Cradle(성공한 행동을 "스킬"로 저장해 재사용), TITAN(MMORPG 테스트, 상태 추상화 + LLM 진단 오라클), 지식 그래프 기반 증분 재테스트. 단점: 긴 실행의 비용·지연, LLM 오라클의 오탐

### 에이전트가 분석하기 좋은 로그
- **Playwright trace**: 액션 NDJSON + 전후 스냅샷 + 로그를 zip 하나로. 구간을 고르면 그 구간 로그만 걸러짐
- **OpenTelemetry GenAI 스팬**: 실행 → 노드 → 도구 호출을 부모·자식 트리로 표현, 기존 관측 도구와 호환(규약은 아직 안정화 중)

### Kookabug 에이전트 연동 구조 초안
- **패널**: ACP 클라이언트 1순위, PTY 탭 보조. 세션을 만들 때 Kookabug MCP와 프로젝트 폴더를 주입. 외부에서 단독 실행하는 경우를 위해 "이 프로젝트에 설정 쓰기" 버튼(변경 내용 diff 미리보기)
- **MCP 툴셋**

| 툴셋 | 도구 예시 |
|---|---|
| core (상주) | `kb_project_info`, `kb_toolset_enable`, `kb_graph_get`, `kb_graph_validate`, `kb_run_status`, `kb_log_search` |
| graph | `kb_graph_create`, `kb_graph_edit` (패치 단위) |
| run | `kb_run_start`, `kb_run_stop`, `kb_run_step` |
| vision (읽기) | `kb_screen_capture`, `kb_screen_find_image`, `kb_screen_ocr`, `kb_screen_zoom` |
| input (위험) | `kb_input_click`, `kb_input_key`, `kb_input_drag` |
| explore | `kb_map_add_screen`, `kb_map_add_transition`, `kb_map_query` |
| resources | `kookabug://graphs/{id}`, `kookabug://runs/{id}/trace`, `kookabug://runs/{id}/failures`, `kookabug://map/screens/{id}` |

- **권한**: Kookabug 서버가 직접 집행(에이전트의 승인을 믿지 않음). 규칙 형식은 `도구(인자 패턴)` (예: `kb_input_*(window:MyGame*)`). 프리셋은 읽기 전용 / 그래프 작성 / 실행 / 전체. 헤드리스 Agent 노드는 ask를 deny로 처리하고 기록
- **Agent 노드**: 입력은 목표(자연어), 허용 툴셋, 예산(스텝·토큰·시간), 성공 판정 스키마. 출력은 success / fail / timeout 분기 + JSON. 성공 궤적을 캐시해서 다음엔 이미지 매칭으로 결정적 재생. 그래프는 자동으로 바꾸지 않고 "결정적 노드로 굳히기" diff를 남겨 사람이 승인
