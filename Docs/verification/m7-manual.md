# M7 사람 확인 절차서

M7(화면 지도) 완료도 두 단계다 ([[구현 계획 v0]] 1장 M7 행).

1. **자동 완료**: CI 자동 검사(가짜 탐색 에이전트 각본 `tools/kb_testing/fake_explorer.py` + 실제 `kookabug mcp`·daemon·runner + 상태를 잇고 입력 값을 그리는 가짜 예제 게임), 인수 테스트(`python/kookabug_core/tests/acceptance/test_m7.py`, `apps/desktop/e2e/acceptance.m7.spec.ts`), 시안 비교 PNG(`tools/design-ref/compare.mjs screenmap screenmap-promote screenmap-protected`), 설치본 스모크 화면 단계(`cli.screen` — 설치 트리 `kookabug screen test`의 OCR 조건 판정, `cli.mcp`의 screens 툴셋 도구), 이 절차서·결과 양식
2. **최종 완료**: 이 절차서의 결과가 결과 양식(`m7-result-template.md`)에 기록되고 모든 항목이 통과 기준을 만족

> M1~M7 사람 확인은 [[mvp-human-check]] 순서로 한 번에 한다(2026-11-05 사용자 결정). 실제 에이전트 CLI·실제 게임·실제 입력은 CI에서 쓰지 않는다 — 여기서만 본다.

| 절 | 내용 | 누가 | 시간 |
|---|---|---|---|
| D1·D2 | 전체 자동 검사·E2E, 설치본 스모크(화면 단계) | 조율자 | 약 1시간 30분 (기다림) |
| H1~H7 | 실제 에이전트 탐색·끼어들기·지도 시안·승격·비밀값·실제 게임·복구 | 사람 | 약 2시간 30분 |
| U1~U14 | 기본값으로 진행한 사용자 결정 | 사람 | 20분 |

결과 `manual_result.md`와 증거 폴더는 레포 밖 `.orchestration/M7/`(git 제외)에 둔다.

- 예제 사본의 `screens/`를 비우고 시작한다(처음부터 탐색). 예제 게임은 `fixtures/sample-game/README.md`대로 띄운다(tkinter, 실제 창)
- 비밀값: `KOOKABUG_SECRET_ACC_ID=qa_tester_01`, `KOOKABUG_SECRET_ACC_PW=sample-pass-01`(예제 기본값)을 앱을 띄우는 셸에 둔다
- 에이전트 CLI(Claude Code·Codex 중 로그인된 것)를 앱 설정의 에이전트로 둔다([[m5-manual]] 0절)
- 권한: 사이드바 "권한"에서 프리셋 "탐색"(`explorer`)

### 자동 검사와 다른 점 (알아 둘 것)

- `kookabug screen test`의 종료 코드 `3`은 **판정 불가**(확인하지 않은 조건만 남음, 판정 조건이 없는 후보, 에이전트가 부른 CLI의 OCR 조건)다. `kookabug run`의 `3`(건너뜀 `skipped`)과 뜻이 다르다
- 에이전트 제어 실행(`kb_input_*`·탐색 클릭)의 실행 기록은 워크스페이스 영상·스크린샷 설정과 무관하게 **이미지 기록이 없고** 비밀값을 가린다(U14). 기록 뷰어 머리 줄에 "에이전트 제어 실행"
- 비밀값을 넣은 창은 칸이 사라진 화면이 확인될 때까지(또는 창이 닫힐 때까지) 에이전트에 이미지를 보내지 않는다(U12). 그 동안 저장한 화면은 "보호로 스크린샷 없음"·판정 조건 없음 후보이고 **승격할 수 없다**
- 다시 탐색했을 때 합치기 후보는 보호가 풀리는 화면(타이틀·로비·월드)에서 나온다

## 2. 사람 확인 (H)

### H1 실제 에이전트 CLI로 예제 게임 탐색

1. 앱 에이전트 패널에서 에이전트에 연결 → "예제 게임을 탐색해서 화면 지도를 만들어 줘. 로그인은 비밀값 acc.id·acc.pw로"
2. 첫 게임 클릭에 확인 카드: [허용]·[이 탐색 동안 허용]만 있고 "항상 허용"이 없다. 세션 이름 옆 "(에이전트가 붙인 이름)". [이 탐색 동안 허용]
3. 상태 바 보라 "Agent 탐색 중 · m:ss", 오른쪽 "입력 도구: 이 탐색 동안 허용됨", 패널 스텝 `n/200`
4. 비밀값 입력 뒤 에이전트가 받은 안내(보호 중·칸을 클릭한 뒤 입력하면 다음 화면에서 풀림)와 그 뒤 행동을 적는다
5. 탐색이 끝나면 보라가 풀리고, 지도 탭에 `screens/_explored/<세션>/` 후보 카드가 보인다

- 기대 결과: 승인 카드·예산·상태 바가 위와 같고, 같은 창·같은 조작은 다시 묻지 않는다. 세션이 끝나면 다음 탐색은 다시 묻는다. 에이전트가 보호 중 안내 때문에 막히면 어디서 어떻게 막혔는지 적는다(남은 리스크)

### H2 탐색 중 실행·녹화 끼어들기

H1 탐색 중에 사람이 그래프를 실행(F5)하고, 다음 탐색 중에는 녹화를 시작한다.

- 기대 결과: 그 동안 에이전트 클릭은 `run_busy`·`recording_active`로 거부되고 게임에 입력이 가지 않는다. 실행·녹화가 끝나면 같은 세션에서 이어 탐색하고, 거부된 클릭은 스텝 예산을 쓰지 않는다. 상태 바는 실행 파랑·녹화 빨강이 보라보다 먼저

### H3 화면 지도 시안 대비·큰 지도

지도 탭을 다크·라이트로 시안(`Docs/Design/UX 시안 v0.1/ScreenMap.dc.html`)과 나란히 본다(샷 `.orchestration/M7/shots/B5/`). 이어 300카드 합성 지도(`screenmap.perf.spec.ts`와 같은 파일)를 연다.

- 기대 결과: 범례는 있는 출처만, 후보 점선, 확인 전 묶음, "보호로 스크린샷 없음", 4단 접기·처음 보기 화면 맞춤이 쓸 만하다. 큰 지도는 30%까지 작아진다 — 확대·끌기·카드 찾기 조작감을 적는다

### H4 승격·합치기·버리기와 그래프 출구

1. 지도 사이드바 "확인 전"에서 후보 하나를 [옮기기] → 대화 상자 확인 → `screens/<id>.screen.json`·`<id>.shot.png`
2. 다시 탐색해서 생긴 합치기 후보를 [합치기], 필요 없는 후보는 [버리기]
3. 옮긴 화면을 출구 `screen`으로 쓰는 그래프 두 개를 이어 실행하면 지도에 실행 기록 간선(주황)
4. 저장 안 한 그래프 탭을 연 채로 승격해도 그 탭·파일이 그대로

- 기대 결과: 파일이 위와 같이 옮겨지고 `kookabug screen test <id> --window SampleRPG`가 맞음(0). 대화 상자 문구·실패 안내가 쓸 만하다

### H5 비밀값을 넣은 탐색 결과 육안 확인

H1 결과 폴더(`screens/_explored/`), 옮긴 화면의 `*.shot.png`, `.kookabug/cache/agent/`, 에이전트 제어 실행 기록(`runs/`)을 연다.

- 기대 결과: 어느 이미지에도 계정·비밀번호 글자가 없다. 비밀값을 넣은 로그인 화면 후보는 이미지가 없다. 제어 실행 기록에 PNG가 없고 이벤트의 입력 값은 가려져 있다. 민감 target(`sensitive: true`)이 보이는 화면도 이미지가 없다(U13)

### H6 실제 게임(레포 밖) 탐색

실제 게임 워크스페이스(레포 밖)에서 H1을 짧게(스텝 예산 30) 한다. 회사·게임 이름은 결과에 적지 않는다.

- 기대 결과: 승인·보호·후보 저장이 예제와 같게 동작. 해상도·DPI가 다른 창에서 이미지 조건이 맞는지 `kookabug screen test`로 본다(남은 리스크)

### H7 남은 승격·보호 기록 손상 풀기

1. **남은 승격**: 승격 중 앱·daemon을 강제 종료한 뒤 다시 열어 지도가 "남은 승격 정리" 안내를 보이면 `kookabug screen recover --show`로 남은 파일·원래 바이트 위치·경고를 본다 → 그 안내대로 한 뒤 `kookabug screen recover`. 사람이 지운 대상 파일이 있으면 원래 바이트는 `.kookabug/screens-tx-kept/<거래>/`에 남는다(확인 뒤 사람이 지운다). 승격 표시 `promoted`는 후보 파일이 아니라 **세션 폴더의 `explore.json`**(`screens/_explored/<세션>/explore.json`의 `promoted["<키>"]`)에 있다 — 잘못 남았으면 `recover --show` 안내가 가리키는 그 항목을 고친다
   - 승격 거래는 수십 ms라 사람이 그 순간에 끊기 어렵다(자동 검사는 실패 주입으로 본다 — `test_m7.py`의 kill 3지점). 여러 번 해도 남은 승격을 만들지 못하면 결과 칸에 `-`(실행 불가)와 사유를 적고 2로 넘어간다
2. **보호 기록 손상**: 앱을 끄고 `.kookabug/agent-protect.json`을 일부러 깨뜨린 뒤 다시 연다

- 기대 결과: 1은 복구 뒤 `screens/`가 승격 전이나 후 중 하나로 일관되고 `recover`가 0. 2는 에이전트 창 이미지가 모두 막히고(`protect_state_unknown`) 사람 연결에 알림, 원본 옆 `.corrupt.<시각>` 사본. 원본을 고치거나 지우고 daemon을 다시 시작하면 풀린다. 비밀값 키 목록만 비울 때는 `kookabug screen protect --clear-keys`(daemon이 꺼져 있을 때)

## 3. 기본값으로 진행한 사용자 결정 (U)

M7 계획 7장. 그대로 둘지 바꿀지 적는다.

| ID | 기본값 |
|---|---|
| U1 | 시안 "권한: 탐색" = 새 프리셋 `explorer`(조회·화면 지도 쓰기 allow, 게임 조작 ask, 그래프 편집·실행 deny). 기본 프리셋은 `graph_author` |
| U2 | "이 탐색 동안 허용" 넣음: 세션·창·도구만, 메모리, 세션 끝·예산 초과·대기 중 끝에 소멸, deny 우선. 게임 실행(`kb_app_launch`)은 제외 |
| U3 | 출처 "녹화"는 MVP 뒤(숨김) |
| U4 | 출처 "문서·영상"은 MVP 뒤, 범례에서 숨김 |
| U5 | 무인 탐색 새 규칙 없음(control을 allow로 둘 때만) |

| U7 | 대표 스크린샷은 긴 변 1280px PNG, 화면 파일 옆 `<id>.shot.png` |
| U8 | 스텝 예산 200(1~1000) |
| U9 | 상세 단추 2개는 에이전트 요청 채우기 |
| U10 | 승격 대화 상자·"확인 전" 묶음은 기존 체계 최소안 |
| U11 | 출처 색은 시안 그대로, 라이트는 토큰 대응 |
| U12 | 비밀값 입력 뒤 그 창 이미지를 에이전트에 보내지 않음(칸이 사라진 화면이 확인될 때까지) |
| U13 | 민감 target이 보이는 화면 이미지를 에이전트에 보내지 않음 |
| U14 | 에이전트 제어 실행 기록은 워크스페이스 D3 설정과 무관하게 늘 비밀값을 가림(이미지 기록 없음) |
