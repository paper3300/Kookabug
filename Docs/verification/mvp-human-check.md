# MVP 사람 확인 안내 (M1~M8 몰아서)

M1~M7 사람 확인을 한 번에 하기 위한 안내다(2026-11-05 사용자 결정: 사람 확인은 M7 끝에 몰아서). M8(자기 진화 QA v1)의 사람 확인도 같은 자리에 더했다. 절차는 각 절차서(`m1-manual.md`~`m8-manual.md`)가 정하고, 이 문서는 **어느 절이 남았는지와 어떤 순서로 할지만** 정한다. 각 절은 원래 절차서의 같은 ID 절을 그대로 따른다.

- 상태: `완료`(결과가 있음 — 근거에 위치·날짜), `실행 필요`, `조건부`(근거에 조건), `이번에는 실행 불가`(근거에 이유)
- 근거의 `.orchestration/…`은 레포에 올리지 않는 작업 기록 폴더(개발자 PC에만 있음)다. "STATE"는 `.orchestration/STATE.md` 작업 기록, "구현 계획"은 [[구현 계획 v0]]
- 앞 마일스톤 D절의 `완료`는 그 마일스톤 시점 결과다. MVP 전체 회귀는 `m7:D1`이 한 번에 본다(M8 뒤에는 `m8:D1`이 M7까지 포함한다)
- 결과는 각 절차서의 결과 양식 사본(`.orchestration/M<N>/manual_result.md`)에 적는다(6단계)

## 1. 실행 순서 요약

상태가 `실행 필요`·`조건부`인 절만 배치했다. 단계 안 순서는 2장 각 단계에 적은 순서대로 한다.

| 단계 | 할 일 | 필요한 것 | 시간(대략) |
|---|---|---|---|
| 0 | 준비 | 인터넷, 에이전트 CLI 2종 계정, 모델 API 키, 공개 GitHub 계정 | 1시간 |
| 1 | Sandbox: 깨끗한 Windows에서 설치본 | Windows Sandbox, 제품 판 설치 파일 | 1시간 30분 |
| 2 | 개발 PC 예제 게임 (같은 앱 세션으로 M2 → M7) | 잠금 해제 PC, 개발 빌드 앱, 에이전트 로그인, 공개 레포(M6) | 자동 2시간(기다림) + 사람 5~6시간 |
| 3 | 개발 PC 실제 게임·실제 외부 환경 | 실제 게임(레포 밖 설치), 에이전트 로그인, 모델 API 키, 인터넷(PyPI), 다른 PC 또는 Sandbox, 다음 판 설치본, 백신이 켜진 PC | 하루 |
| 4 | 로그아웃이 필요한 것 | 로그아웃할 수 있는 시간, 잠금 해제 PC | 40분 |
| 5 | 화면 시안 대비 한 번에 | 레포 PC, 최신 빌드, 시안 PNG | 3시간 |
| 6 | 결과 정리 | 결과 양식 사본 | 1시간 |

## 2. 단계별 할 일

### 0. 준비

- **설치 파일**: 최신 main의 CI `installer` 잡 artifact에서 제품 판 `kookabug-setup-<버전>.exe`(1·3단계)를 받는다(또는 `m1-manual.md` S2 명령으로 만든다). 이전 확인에 쓴 3d4fe47 판은 쓰지 않는다
- **Sandbox**: `m1-manual.md` S1(이미 켜짐, 2026-11-05) 확인, `Docs/verification/m1-sandbox.wsb`를 `C:\kookabug-m1\`로, 설치 파일을 `C:\kookabug-m1\in\`으로
- **실제 게임**: SuperTuxKart(또는 다른 공개 GPU 게임)를 레포 밖에 설치한다. 게임 이름·화면은 레포 밖 결과에만 적는다(`m1-manual.md` 머리말)
- **에이전트 CLI 2종**: 설치·로그인(`m5-manual.md` 0절 감지 표의 명령 후보). M5·M7·M8이 같이 쓴다
- **비밀값**: 예제 비밀번호는 환경 변수 `KOOKABUG_SECRET_ACCOUNTS_QA_TESTER_01`(M2~M6), M7 탐색은 `KOOKABUG_SECRET_ACC_ID`·`KOOKABUG_SECRET_ACC_PW`(각 절차서 0절), 모델 API 키는 자격 증명 관리자나 `KOOKABUG_SECRET_<키>`로만. 파일에 쓰지 않는다
- **공개 레포**: `examples/plugins/kookabug-plugin-sample`을 개인 공개 GitHub 레포로(`m6-manual.md` 0절, 태그 `v0.1.0`)
- **결과 양식**: `m1-result-template.md`~`m8-result-template.md`를 `.orchestration/M1/`~`M8/`에 `manual_result.md`로 복사한다(있으면 두고, `M3`에는 빈 사본이 이미 있다). 증거 폴더는 각 절차서 0절의 `$ev`
- **PC**: 설정 → 시스템 → 전원의 화면 끄기·절전 "안 함", `uv sync --locked --all-packages`, 앱 빌드(각 절차서 0절)

### 1. Sandbox (깨끗한 Windows·설치본)

`m2-manual.md` 5절 · `m3-manual.md` 6절. 한 Sandbox에서 이어서 한다.

- `m2:S1` → `m2:S2` → `m2:S3`(이 설치가 `m3:S1`) → `m2:S4` → `m3:S2` → `m3:S3` → `m2:S5`(이 제거가 `m3:S4`)
- 조건부: `m2:S6`(PowerShell이 막힌 PC가 있을 때 그 PC에서), `m3:S5`(Windows N·KN 판 PC·VM을 구했을 때 그 PC에서)
- 선택: 같은 설치본으로 `m1-manual.md` S4·S5를 다시 돌려 보면 2026-11-05 결과(옛 설치 파일)를 새 판으로 갱신할 수 있다

### 2. 개발 PC 예제 게임 (같은 앱 세션으로 M2 → M7)

- `m7:D1`(전체 자동 검사 — `m4:D2`·`m5:D2`·`m6:D1`도 이 한 번으로 결과를 적는다) → `m5:D1`. 설치본 스모크(m7 D2)는 B6에서 끝났다(전수 표) — CI `installer` 잡 녹색만 push 뒤 확인. M8 끝 전체 검사는 `m8:D1`(M7까지 포함) — `m8:D2`(설치본 스모크 QA 단계)와 함께 아래 3장 근거를 본다

### 4. 로그아웃이 필요한 것

- `m1:D7`의 남은 부분: 로그온 때부터 높은 배율(system-aware 창 실측). 설정에서 사용자 지정 배율 150 → 로그아웃·로그인 → `m1-manual.md` D7 명령(`d7_dpi150.log`) → 200으로 같은 일 → 100%로 돌린다
- 실패하면 축소되는 system-aware 창의 `set_client_size` 결과(비정수 역변환 크기)를 적는다
