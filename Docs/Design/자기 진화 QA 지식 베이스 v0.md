## 0. 사용자 결정 (고정 전제)

1. **사람 확인을 최소화한다.** Init은 테스트 케이스를 만드는 작업이 아니다. 이후 AI가 테스트를 작성하고 플레이할 수 있도록 **프로젝트 정보를 모으는 작업**이다. 테스트가 실패하거나 중간에 진행이 막히면, AI가 원인(UI·UX 변경, 기획 변경, 버그 등)을 스스로 찾고 고친 뒤 보고한다.
2. **추측한 기대 결과를 허용한다.**
3. **치트를 허용한다.** 허용 범위는 테스트 케이스별 옵션으로 정한다.
4. **목표**: Agent가 Kookabug로 QA를 하면서 스스로 진화하는 시스템을 만든다. 로드맵과 필요한 정보를 자체 위키로 구성하고, 그 위키를 스스로 갱신한다.

## 1. 목표와 성공 기준

**목표**: 게임이 빌드마다 바뀌어도 Agent가 아래 일을 반복할 수 있어야 한다.

- 무엇이 바뀌었는지 알아낸다.
- 테스트를 고치고, 고칠 수 없는 것은 근거와 함께 남긴다.
- 지식을 쌓는다.

사람은 묶음 보고만 받는다.

**성공 지표**: 위키 페이지 수나 수리 후 통과율은 지표가 아니다. 아래 두 가지가 지표다.

- **근거가 연결된 조사 완료**
- **기준을 바꾸지 않은 수리 성공**

"잘 고치는 시스템"이면서 동시에 **"버그를 지우지 않는 시스템"**이어야 한다.

## 2. Karpathy LLM Wiki와 다른 점

LLM Wiki는 세 층과 세 연산으로 이루어진다.

- 층: 바꾸지 않는 원본(raw), LLM이 유지하는 마크다운 위키, 스키마(AGENTS.md)
- 연산: ingest, query, lint
- `index.md`·`log.md`를 둔다

Kookabug도 이 뼈대를 쓰되, 다음이 다르다.

| | LLM Wiki | Kookabug |
|---|---|---|
| 원본 | 사람이 고른 문서 | 대부분 **관찰**이다: 실행 기록·탐색·스크린샷. 문서(기획·데이터·패치 노트)는 일부다 |
| 검증 | 사람이 읽고 판단한다 | 주장은 **게임을 돌려 검증할 수 있다**. 주장과 그것을 확인하는 검증 노드를 연결한다 |
| 시간 | 없다 | **빌드·데이터 revision 축**이 있다. 옛 사실은 지우지 않고 무효화한다(Graphiti식). 그 이력이 "기획 변경" 판별의 근거가 된다 |
| 출처·신뢰 | 없다 | 주장마다 근거를 원본까지 추적한다. 추측·관찰·의도를 구분한다 |
| 구조물 | 마크다운뿐 | 화면 지도·target·그래프가 이미 기계용 형식이다. 위키는 이것들을 복제하지 않고 **ID로 참조**한다 |
| 진화 동력 | 새 문서 ingest | **실패**가 동력이다: 사건 → 조사 → 수리 → 재검증 → 지식 갱신 |
| 갱신 | LLM이 페이지를 고쳐 쓴다 | 판정에 쓰는 지식은 **ID·revision 기반의 제한된 연산(delta)**으로만 바꾼다. 결정적 적용기가 충돌을 검출한다(ACE·Mem0식) |

## 3. 핵심 원칙

1. **관찰 ≠ 의도.** "게임이 120골드를 받았다"는 관찰이다. "의도된 가격이 120골드다"와는 다르다. 관찰은 기대 결과를 덮어쓰지 않는다. 둘이 다르면 사건이 된다.
2. **추측은 가설이다.** 추측한 기대 결과로 테스트를 만들고 실행해도 된다(결정 2). 결과는 "가설 일치·불일치"로 해석하고, 불일치만으로 어느 쪽이 틀렸는지 확정하지 않는다.
3. **분류명이 수리 권한을 주지 않는다.** 증상·원인 가설·조사 상태·허용 조치를 분리한다. 여러 가설이 동시에 살아 있어도 된다.
4. **수리는 검증 의미를 지킨다.** 원래 실패, 원래 기준 revision, 원래 기대값을 고정한 채로 고친다. 수리 후 통과가 원래 실패를 덮어쓰지 않는다. 우회 경로나 치트로 얻은 성공은 원래 경로를 복구한 것이 아니다.
5. **미확정을 허용하되 묻어 두지 않는다.** 판단하지 못한 사건은 "필요한 추가 정보"와 재조사 조건을 붙여 열어 두고, Agent는 다른 일을 계속한다.
6. **자기 인용 금지.** 위키를 인용하면 원본 근거까지 추적한다. 같은 실행이나 같은 문서에서 파생된 요약 여러 개를 독립 근거로 세지 않는다. 요약·검색 횟수로 신뢰도를 올리지 않는다.
7. **지식은 지시가 아니다.** 위키에서 정책·플레이북·권한으로 올라가는 경로를 막는다. 위키 내용으로 `AGENTS.md`·스킬을 자동 갱신하지 않는다.
8. **강제는 도구로 한다.** 안전 규칙은 위키 문구가 아니라 권한 프리셋·MCP 도구·실행기 검사에서 강제한다.

## 4. 층과 쓰기 경계

| 층 | 내용 | 누가 쓰나 | 위치 |
|---|---|---|---|
| **원본** | 실행 기록, 탐색 결과, 고정한 증거 묶음, 외부 원본(기획·데이터·패치 노트)의 위치와 해시 | Kookabug(기록)·사람(원본 위치) | `runs/`(Git 제외), `knowledge/evidence/`, `kookabug.json#sources` |
| **지식** | 주장, 사건, 경험칙, 산문 위키 | Agent(제한 연산), 사람 | `knowledge/`, `wiki/` |
| **실행 산출물** | 그래프, target, 화면 지도, 치트 정의 | Agent는 후보·작업 기준까지, 팀 기준은 채택 정책·사람 | `tests/`, `subgraphs/`, `targets/`, `screens/`, `knowledge/cheats.json` |
| **정책** | 권한 상한, 금지 동작, 자동 채택 범위, 치트 분류(사용자 정의)와 무인 허용, 예산 | **사람만** | `kookabug.json`, `.kookabug/local.json`, 사용자 설정 |
| **플레이북** | Init·조사·수리·탐색·작성·정리 지침 | **제품**(버전 있음) | 설치본, `AGENTS.md` 관리 구간 |

**보안 경계를 명시한다.** 외부 Agent(Claude Code·Codex)가 같은 사용자 권한으로 임의 shell을 쓸 수 있으면, Kookabug MCP의 검사만으로는 그 Agent를 통제할 수 없다. Kookabug가 보장하는 범위는 **Kookabug가 제공하는 경로(MCP·`KOOKABUG_AGENT` CLI·`agent-job`) 안**이다. 무인 실행의 안전은 제한된 외부 실행 환경(Agent CLI 자체의 권한 설정)을 전제로 한다.

## 5. 워크스페이스에 더하는 것

```
workspace/
├─ kookabug.json              + sources(원본 위치), automation 정책(자동 수리·금지 동작·예산), cheats 정책(사용자 정의 분류)
├─ knowledge/                 판정에 쓰는 구조화 지식 (커밋)
│  ├─ features/<기능>.json     기능별 주장 배열 (파일 revision + 주장별 revision)
│  ├─ cases/<사건>.json        조사 사건: 증상·가설·상태·필요한 정보·관련 실행
│  ├─ evidence/<묶음>/         고정한 증거 묶음 (가림 처리된 최소 증거 + manifest)
│  ├─ lessons.json            경험칙 (근거·적용 조건·활성 상태)
│  ├─ cheats.json             치트 정의 (ID·인자 스키마·구현 revision·효과·환경·채택 상태)
│  ├─ unknowns.json           미지수 (Init·조사가 남김, 답은 사람만)
│  ├─ working/                작업 기준 변경분 (팀 기준 revision + 변경분, `claims/`는 주장 덧씌움)
│  ├─ adoptions/<채택>.json    자동 채택·묶음 수락·되돌리기 기록
│  ├─ reports/<작업>.json      작업 보고 (보고함·`wiki/reports/` 렌더의 원본)
│  └─ log.jsonl               지식 변경 감사 이력 (연산·근거·작업 ID)
├─ wiki/                      산문 위키 (커밋, Agent가 자유롭게 씀)
│  ├─ index.md                목차 (Kookabug가 생성)
│  ├─ log.md                  사람이 읽는 변경 일지 (log.jsonl에서 생성)
│  ├─ overview.md, glossary.md, roadmap.md, environment.md
│  ├─ features/<기능>.md       기능 설명 + 주장 표(주장 JSON에서 렌더) + 화면·테스트 링크
│  └─ reports/<날짜>-<작업>.md  작업 보고 (당시 revision 기준으로 렌더)
└─ .kookabug/cache/knowledge/ 재생성 가능한 색인
```

- **증거 수명**: `runs/`는 Git에서 제외되고 보관 정책으로 지워진다. 그래서 채택이나 사건 판단에 쓴 실행은 `knowledge/evidence/`에 **가림 처리된 최소 증거 묶음**(manifest, 실패 스텝 이벤트, 화면 차이 썸네일, 환경)으로 고정한다. 근거가 사라졌으면 "검증 불가"로 표시한다.
- **관찰 불가**: D7·D8 때문에 이미지가 없거나 화면이 보호될 수 있다. 이미지가 없다고 대상이 없다는 뜻은 아니다. 위키 기능을 이유로 보호를 우회하지 않는다.

## 6. 지식 형식

### 주장 (`knowledge/features/<기능>.json`)

```json
{
  "format": "kookabug.claims/0",
  "feature": "shop",
  "revision": 14,
  "claims": [
    {
      "id": "shop.potion.price",
      "rev": 3,
      "kind": "expected",
      "statement": "체력 물약 1개 가격은 100골드다",
      "subject": "item:potion_hp_s",
      "property": "price",
      "value": 100,
      "unit": "gold",
      "preconditions": ["상점 NPC 기본 상점", "할인 이벤트 없음"],
      "scope": {"profiles": ["dev"], "builds": {"from": "1203"}, "data_rev": null, "locale": "ko"},
      "basis": [
        {"type": "source", "ref": "sources:item_table#potion_hp_s", "hash": "sha256:…", "seen_at": "2026-11-09T10:00:00Z"}
      ],
      "status": "supported",
      "verified_by": [{"graph": "tests/shop/buy_potion.graph.json", "node": "n_assert_price"}],
      "supersedes": {"id": "shop.potion.price", "rev": 2}
    }
  ]
}
```

- `kind`: `expected`(의도된 동작), `observed`(관찰), `guess`(추측)
- `status`: `hypothesis` / `supported` / `conflicted` / `superseded` / `unverifiable`. 신뢰도를 숫자 하나로 합치지 않는다.
- 시간축은 두 개다. **적용 범위**(`scope`: 빌드·데이터 revision·프로필·언어)와 **알게 된 시각**(`basis[].seen_at`, 감사 이력)을 구분한다. 처음 본 빌드를 유효 시작으로 취급하지 않는다.
- 주장 ID는 안정적으로 유지하고 중복을 허용하지 않는다. 테스트는 **주장 ID + 주장 rev**에 묶인다. 같은 파일의 다른 주장이 바뀌어도 테스트의 기대값 revision은 바뀌지 않는다.
- 산문 페이지는 주장 표를 렌더해서 보여 준다. 평소 위키는 최신 상태를, 보고서는 당시 revision을 보여 준다.

### 사건 (`knowledge/cases/<사건>.json`)

실패나 진행 막힘 하나, 또는 같은 원인으로 묶인 여러 실패를 담는다.

| 축 | 값 |
|---|---|
| 증상 | `target_missing` · `value_mismatch` · `unexpected_screen` · `stalled` · `launch_failed` · `node_error` |
| 원인 가설(여러 개) | `product_regression` · `intended_change` · `ui_change`(같은 의미, 다른 모습·위치) · `flow_change` · `test_defect` · `environment` · `intermittent` |
| 가설마다 상태 | `open` · `supported` · `refuted` · `confirmed` |
| 허용 조치 | `reobserve` · `rerun` · `repair_candidate` · `baseline_change` |
| 판단 불가 시 | **필요한 추가 정보**: 판단을 막는 미지수, 필요한 관찰·원본, 그것이 가설을 어떻게 가르는지, 수집 방법, 필요 권한·예산, 사람만 줄 수 있는지 여부 |
| 재조사 조건 | 새 빌드, 새 원본, 새 증거, 기한 |

- "추가 로그 필요"는 쓸모없다. "이 빌드의 아이템 데이터 revision이 없어서, 의도된 가격 변경과 잘못된 배포를 구분할 수 없음" 정도로 구체적이어야 한다.
- 같은 문맥(테스트·주장 revision, 환경, 관련 산출물, 원본 변경 여부가 같음)의 반복 실패는 **실패 시그니처**로 기존 사건에 붙이고, LLM 분석을 반복하지 않는다. 새 증거나 환경 변경이 생기면 캐시를 무효화한다. 같은 시그니처라고 같은 원인으로 확정하지는 않는다.
- 재실행으로 통과했다고 `flaky`로 확정하지 않는다. `intermittent` 관찰로 기록한다. 불안정 이력을 버그를 할인하는 근거로 쓰지 않는다.

### 원인 판별: 무엇이 무엇을 지지하나

| 가설 | 지지 근거 | 확정에 필요한 것 |
|---|---|---|
| `ui_change` | 같은 화면이 판정되고(화면 지도), 같은 의미의 요소가 다른 위치·모습으로 발견된다 | 수리 후 **원래 기대 결과로** 전체 통과 + 음성 대조 |
| `flow_change` | 예상 밖 화면이 나오고, 그 화면을 넘기면 원래 흐름이 이어진다 | 탐색으로 새 이동을 확인. 오류 팝업이 아님을 판정 |
| `intended_change` | 권위 있는 원본(사람이 `sources`에 지정)의 변경이 **그 명제에 정확히 연결**되고, 배포 revision이 일치한다 | v1은 작업 기준에만 반영하고, 팀 기준은 묶음 보고에서 수락 |
| `product_regression` | 지지되는 `expected` 주장과 관찰이 다르고, 변경 근거를 찾지 못했다 | 확정하지 않는다. "회귀 의심"으로 보고한다. 근거를 못 찾은 것과 변경이 없는 것을 구분한다 |
| `test_defect` | 원래 기대 결과를 바꾸지 않고 테스트 구현의 오류를 설명할 수 있다(예: 100을 읽고 1,000을 넣음) | 수리 후 원래 기대로 통과 |
| `environment` | 게임·창·서버·해상도 문제가 비교에서 드러난다 | 새 빌드의 시작 크래시와 구분한다 |

판별 신호는 다음과 같다. 원인을 판정해 주는 도구는 없고, 신호는 증거를 모으는 데까지만 쓴다.

- `kb_run_compare`(기준 실행 대비 그래프·환경·빌드·시간·화면 차이)
- 실패 프레임 `kb_screen_identify`
- 변경하지 않은 테스트로 제한 횟수 재현
- 원본 diff
- 주장의 `kind`·`status`

### 경험칙 (`knowledge/lessons.json`)

예: "로그인 뒤 공지 팝업이 늦게 뜬다. 닫기 전에 공지 화면을 기다려라."

- 관찰(약 2초 뒤에 나타남)은 주장으로, 행동 조언은 경험칙으로 나눈다.
- 경험칙에는 근거 실행, 적용 환경·빌드·전제, 활성 상태를 둔다.
- 경험칙은 고정 대기를 넣거나 타임아웃을 늘리는 권한이 아니다.
- v1은 저장·근거·활성 상태까지만 다룬다. ExpeL식 투표 점수는 사용 데이터가 쌓인 뒤 **검색 우선순위로만** 도입한다. 진실성이나 권한의 척도로 쓰지 않는다.

### 지식 변경 연산

Agent는 페이지나 파일 전체를 다시 쓰지 않는다. 아래 연산만 쓴다.

- `add`
- `revise`(새 rev)
- `supersede`
- `mark_conflicted`
- `attach_evidence`
- `set_status`

각 연산에는 대상 ID와 기준 revision을 붙인다. 적용기는 형식 충돌과 revision 충돌을 검출한다. 형식상 합칠 수 있어도 의미가 모순되면 조용히 하나를 고르지 않고 `conflicted`로 남긴다. 모든 연산은 `log.jsonl`에 남는다(연산, 근거, 작업 ID, Agent 종류·모델).

산문 위키(`wiki/`)는 Agent가 자유롭게 쓴다. 대신 판정 근거로 쓰이지 않는다. 산문이 판정에 영향을 주려면 주장으로 올려야 한다.

## 7. 두 기준: 팀 기준과 작업 기준

사람 확인을 줄이면서 팀 기준(CI)이 낡지 않게 하려고 기준을 둘로 나눈다.

| | 팀 기준 | 작업 기준 |
|---|---|---|
| 무엇 | 팀이 채택한 그래프·target·화면 지도·주장 | 팀 기준 revision + Agent 변경분(`knowledge/working/`, 후보 화면) |
| 기본 사용처 | 팀 회귀 검사·CI·사람 실행 | Agent의 조사·작성·탐색 작업 |
| 갱신 | 사람 채택, 또는 좁은 **자동 채택 정책** | Agent가 즉시 반영 |

- 기준은 **호출자가 Agent인지로 정하지 않는다.** 작업 종류로 정한다. CI도 무인 Agent로 돌 수 있기 때문이다.
- 실행 시작 때 기준과 그 revision을 고정하고 `run.json`에 기록한다. 실행 도중 작업 기준이 바뀌어도 반영하지 않는다.
- 팀 기준이 바뀌면 작업 변경분과의 충돌을 검사한다. 오래된 작업 변경이 팀 수정을 조용히 가리지 않게 한다.
- 작업 기준의 화면 정의는 **Agent가 유지하는 가설**이다. 후보 화면으로 판정한 결과를 그 후보가 정당하다는 근거로 다시 쓰지 않는다. 조건이 겹치는 화면은 모호성으로 처리한다.
- **화면 지도의 팀 승격은 D6 그대로 사람만 한다.**

### 자동 채택 (v1: 조작용 locator 수리만)

모든 조건을 만족할 때만 팀 기준으로 자동 채택한다.

1. 정책이 켜져 있고 범위(테스트 폴더·프로필) 안이다. **기본값은 켬**(범위 `tests/` 전체, 사용자 결정). 첫 프로젝트 설정 마법사(13장)에서 끄거나 범위를 바꾼다. Agent는 이 정책을 바꿀 수 없다. 테스트에 `qa.claims`가 없으면 필수 검증 노드를 정할 수 없어 자동 채택하지 않는다(작업 기준 + 보고).
2. 변경이 **조작할 대상을 찾는 locator**뿐이다. 이것은 Agent가 선언하는 것이 아니라 허용 필드·의존성 diff로 **결정적으로 검사**한다. 판정에 직간접으로 쓰이는 target이나 조작·판정이 함께 쓰는 target은 제외한다. 임계값을 낮추거나 검색 범위를 넓히는 변경도 제외한다.
3. 판정 노드, 주장 revision, **검증 의존성**(판정이 읽는 target·OCR 영역·화면 조건·서브그래프)이 바뀌지 않았다.
4. 고정한 주장 revision의 **필수 검증 노드가 실제로 실행되어** 통과했다. 전체 판정 `pass` 하나로는 부족하다.
5. **음성 대조**를 통과했다. 기존에 보존한 다른 화면이나 비슷한 다른 버튼에서는 새 locator가 실패해야 한다. 새로 만든 대조 사례에는 출처와 생성 경위를 남긴다.
6. 그 target·서브그래프를 쓰는 다른 테스트도 재실행해 통과했다.
7. 정책 기준 revision에 대한 **누적 변경**이 상한 안이다. 넘으면 작업 기준에만 남기고 자동 채택을 멈춘다.
8. 기존 revision 대조·거래·저널·복구 계약(D6 구현)으로 게시한다. 원래 실패 실행과 이전 revision은 증거 묶음으로 보존한다.

나머지 변경(기대값, 화면 조건, 흐름, 판정용 target)은 작업 기준에만 반영한다. 사람에게는 **같은 원인끼리 묶은 보고**로 한 번에 보여 준다(Applitools식 묶음 수락).

"되돌리기"는 **산출물 revision 복구**에 한정된다. 게임 계정·서버 상태의 변경은 되돌릴 수 없다.

## 8. 진화 루프

```
트리거 (사람 요청 / 예약 / CI 실패)
  → 관찰: 실행, 기준·revision 고정
  → 사건: 시그니처로 기존 사건에 붙이거나 새로 연다
  → 조사: 예산 안에서 가설을 가장 잘 가르는 탐침(재현·비교·화면 판정·원본 diff·탐색)
  → 수리 후보: 작업 기준에 반영 (원래 실패·기대값 고정)
  → 재검증: 원래 기대 결과로, 필수 검증 노드·음성 대조·영향 테스트
  → 채택: 자동 채택 정책 또는 묶음 보고
  → 지식 갱신: 제한 연산, 산문 위키·보고서 렌더
  → 판단 불가: 필요한 추가 정보 + 재조사 조건으로 열어 두고 다음 일로
```

- **정체 감지**(v1): "같은 상태에서 같은 실패 행동 반복"이나 전체 기한을 넘으면 조사 방향을 바꾸거나 멈춘다. 반성은 무제한 반복하지 않는다. 정체를 제품 버그로 확정하는 오라클로 쓰지 않는다.
- **버그 은폐 방지**: 실패한 원래 경로를 우회나 치트로 넘겨 이후 테스트를 계속할 수는 있다. 그래도 원래 사건은 열린 채로 남는다.

## 9. Init

Init은 테스트를 만들지 않는다. **이후 작업을 시작할 수 있는 지식과 미지수를 정리**하면 끝난다.

| 단계 | 결과물 | 막히면 |
|---|---|---|
| 1. 설정 확인 | 첫 프로젝트 설정 마법사(13장)가 이미 정한 것을 읽는다: 실행 파일·창·해상도·계정 키·Agent·원본 위치·자동화 정책. 빈 칸은 미지수로 기록하고 Init 안에서 다시 묻지 않는다 | — |
| 2. 원본 수집 | `overview`·`glossary`·`roadmap`·기능 목록, 기능별 주장 후보(`expected`/`guess`), 치트 후보 | 원본이 없으면 "없음"으로 남긴다 |
| 3. 환경 진단 | 실행 → 창 → 해상도 확인, 가능하면 로그인 서브그래프 | 미확정 사건 |
| 4. 기능 지도 | `기능 → 화면 → 주장 후보`. 예산 안에서 탐색 | 미탐색·미연결 상태를 허용한다. 그럴듯한 연결로 채우지 않는다 |
| 5. 보고 | 알게 된 것, 모르는 것, 다음 수집 작업 | — |

- **로드맵**에는 원본이 확인된 게임 일정(업데이트·기능)만 적는다. 원본이 없으면 "확인된 향후 일정 없음"으로 둔다. Agent가 제안하는 QA 작업 계획은 따로(`wiki/roadmap.md`의 "QA 계획" 절) 두고 둘을 섞지 않는다.
- Init이 끝나면 상시 루프가 기능 지도의 빈 곳(주장은 있는데 검증 노드가 없음)부터 테스트를 작성한다.
- (2026-11-11 UX2) 원본은 Kookabug 도구 `kb_source_list`·`kb_source_read`로만 읽는다: 등록된 원본(`kookabug.json#sources`·`local.json`) 루트 아래만(워크스페이스 밖 폴더도), 링크·정션·`..`·워크스페이스 파생 폴더 거부, URL은 받지 않음, 텍스트·docx·xlsx·pptx 글만, 200 KB씩 `offset`으로, `agent.log`와 같은 가림. 결과의 `ref`·`hash`가 곧 `source` 근거다.
- (2026-11-13 UX5, 사용자 결정 — [[설정·Init 간소화 v0]] 5·6절) **Init 범위를 줄인다**: 설정 확인 → 원본 러프 수집(`overview`·`glossary`·`environment`, 기능별 한 줄 `features/<기능>.md`, 원본에 바로 보이는 주장 후보만) → 게임 실행·창·첫 화면·종료 → `게임 실행`·`게임 종료` 서브그래프(`subgraphs/common/`, 저장 뒤 실행 확인) → 보고. 위 표의 4단계 기능 지도·로그인은 하지 않는다. **Init·이어 하기는 사람 질문을 만들지 않는다**(도구가 `question_limit`로 거부, 궁금한 것은 위키 "모르는 것", 실행·종료가 막히면 사건 `needs_info` 막힘 보고 → 보고함 "막힘" → 사람이 설정을 고친 뒤 "이어서 진행"). 먼저 직접 알아본다(런처 단추·게임 창·종료 방법·실행 인자·장르). 다음 단계 `entry`(접속 경로, 사람이 보고에서 눌러 시작)는 로비까지 `게임 접속` 서브그래프를 만들고, 사람 질문은 테스트 계정(`kind: credential` + `secret_keys`)뿐이다.
- (UX2) **Init 뒤 이어 하기**: 사람은 보고함 질문에 답하고("답 보내기" 한 번) "이어서 진행"을 누른다 → `followup` 플레이북 무인 작업(9단계 Init과 같은 생성 경로·예산, 사람만 만든다). Agent는 답(`unknowns` answered)을 읽고, 설정에 해당하는 답은 `kb_setting_propose`로 **제안만** 하며(보고 항목 `setting_change`, 사람이 수락), 원본을 다시 모아 위키·주장 후보를 고치고, `roadmap.md` "QA 계획"대로 4단계를 이어 간다. 이미 답한 것은 다시 묻지 않는다.
- (2026-11-12 UX3, 사용자 결정) **읽기 허용 폴더**: 실행 bat·서버 목록 json처럼 원본이 아닌 프로젝트 밖 파일은 원본(기획 근거)과 따로 둔 "읽기 허용 폴더 목록"에서 같은 도구(`kb_source_list`·`kb_source_read`, id `read:<순번>`, 자동 포함은 `read:game`·`read:game_cwd`)로 읽는다. **실행·환경 확인용 파일은 읽기 허용 폴더에서 읽고, 기획 근거는 원본에서 찾는다** — 읽기 허용 폴더 파일의 ref(`read:<…>#<경로>`)는 `source` 근거가 아니다(`basis_unknown`).
  - 설정: 이 PC `.kookabug/local.json` `settings."agent.read_roots"`(폴더 절대 경로 목록, 20개까지). 팀 설정에는 두지 않는다. 실효 `game.executable`의 폴더와 실효 `game.cwd`는 계산해서 자동 포함한다(설정 파일에 쓰지 않음).
  - 허용하지 않는 폴더(저장·읽기 둘 다 거부, 지정 경로·실경로 둘 다 본다): 드라이브 루트, 사용자 프로필 폴더 자체와 그 바로 아래 `AppData`, Windows 폴더(그 아래 전부), Program Files 루트, 워크스페이스를 품는 폴더(워크스페이스 자체 포함), 워크스페이스 파생 경로, 민감한 이름 폴더. 자동 포함 폴더가 해당하면 빼고(`refused`) 6단계에 경고를 보인다. 폴더 안의 워크스페이스 보호 경로는 UX2 규칙대로 막는다.
  - (검수 1) 확장·장치 경로 접두사(`\\?\`·`\\.\`·`\??\`, `/` 변형 포함)는 읽기 허용 폴더 저장·설정 값·자동 포함·원본 루트 모두 입구에서 거부(`device_path`)하고, 후보·워크스페이스·금지 폴더(환경 변수)는 한 정규화(실경로 → 긴 이름 → `normcase`)로 비교한다. 끝 `.`·끝 공백 경로 조각은 원본·읽기 허용 폴더 모두 거부(`odd_name`)하고, 민감한 이름은 실제로 풀린 긴 이름 조각에도 검사한다(8.3 우회 차단).
  - 읽기 허용 폴더 안에서 거부하는 이름(대소문자 무시, 목록에서도 뺀다): `.ssh`·`.gnupg`·`.aws`·`.azure`·`.git` 폴더 안, `*.pem`·`*.key`·`*.pfx`·`*.p12`·`*.kdbx`, `.env`·`.env.*`, `id_rsa*`·`id_ed25519*`, `credentials*`, `*.keystore`·`*.jks`. 단순 이름 목록(Low 강도)이라 **완전한 차단이 아니다** — 민감한 폴더는 넣지 않는 것이 먼저다. 경계·크기·형식·가림·활동 목록은 원본과 같은 코드 경로다.
  - Agent는 프로젝트 밖 파일이 필요하면 원본 등록을 묻기 전에 `kb_setting_propose`(`agent.read_roots.add`, 폴더 하나, 같은 검사, 값은 이 PC `proposals.json`에만)로 읽기 허용 폴더 추가를 제안한다. 기획 근거가 필요하면 원본 추가 제안이 맞다.

## 10. 테스트별 옵션 `qa`와 치트

### `qa`는 테스트 그래프 최상위의 정식 필드다

`meta`에 넣지 않는다. 실행을 막거나 허용하는 의미가 있기 때문이다. 스키마·실행기·편집기·스냅샷 계약이 함께 바뀐다. 이 필드를 지원하지 않는 실행기는 실행을 거부한다.

```json
"qa": {
  "format": "kookabug.qa/0",
  "feature": "shop",
  "claims": [
    {"id": "shop.potion.price", "rev": 3, "assertions": ["n_assert_price"]}
  ],
  "cheats": {
    "allow": [
      {"id": "give_gold", "args": {"amount": {"max": 1000}}, "max_calls": 1}
    ]
  },
  "profiles": ["dev"],
  "repair": {"allowed_changes": ["locator"], "preserve_oracle": true}
}
```

- `claims`는 **이 테스트가 검증하는 주장 revision과 검증 노드**를 연결한다. 테스트 전체 통과만으로 모든 주장을 검증했다고 처리하지 않는다. 커버리지는 "그 검증 노드가 어떤 조건에서 실제로 실행됐나"로 센다.
- `cheats.allow`는 테스트가 **요청하는** 범위다. 그 자체가 권한 부여는 아니다. 실제로 허용되는 범위는 워크스페이스 상한, 실행 세션 권한, 루트 테스트 범위, 서브그래프 제약을 **모두** 만족하는 부분이다. 서브그래프가 권한을 넓힐 수 없다.
- 프로필이 대상이 아니면 미적용으로 처리한다. 잘못된 치트 참조, 권한 위반, 구현 누락은 **설정 오류**로 드러낸다. skip으로 묻지 않는다.
- `phase`(setup/body/teardown) 제한은 v1에 넣지 않는다. 실행기가 그 경계를 실제로 구현하기 전에는 제한을 제공한다고 주장하지 않는다. 그 대신 치트 사용 기록에 "판정 노드보다 앞인지 뒤인지"를 남긴다.

### 치트 정의 (`knowledge/cheats.json`)

- **엔진 무관 인터페이스**: 치트 ID, 인자 스키마와 범위, 효과 설명, 전제 조건, **분류**(사용자 정의), 대상 환경
- **구현**: 고정 템플릿에 검증된 인자만 넣는 콘솔 입력 서브그래프, 또는 설치된 엔진 플러그인 노드. 인자에 명령 구분자나 추가 구문을 넣을 수 없게 검사한다. 위키의 자유 문자열을 실행하지 않는다.
- **분류는 Kookabug가 정하지 않는다**(사용자 결정). 위험의 기준은 게임·프로젝트마다 다르다. 사용자가 `kookabug.json#cheats.categories`에 분류를 직접 만들고(이름·설명·무인 실행 허용 여부), 제품은 기본 분류를 넣지 않는다. Kookabug가 강제하는 것은 다음 메커니즘뿐이다.
  - 분류가 없거나 채택되지 않은 치트는 무인 실행에서 쓰지 않는다.
  - 분류의 무인 허용 여부를 따른다.
  - Agent는 분류를 확정하지 못한다.
- **채택**: Agent가 후보를 추가한다(코드에서 찾은 것 포함). 사람이 **명령 단위로 한 번** 채택하면서 분류를 정한다. 채택 대상은 `ID + 구현 revision + 인자 스키마 + 대상 환경 + 효과 범위` 묶음이다. 정의가 바뀌면 기존 채택이 따라가지 않는다. 프로필 이름이 `dev`라고 안전한 서버로 간주하지 않는다.
- **보장 범위**: 범용 control 권한이 있는 실행에서는 Agent가 콘솔에 직접 칠 수 있다. 이때 카탈로그는 추적과 권장 경로일 뿐, 미등록 치트 사용을 막지 못한다. "채택된 치트만"을 보장하려면 임의 control 입력을 막은 **제한된 무인 실행**이 필요하다(권한 프리셋 `qa_runner`, 아래).

## 11. Kookabug 내장 vs 외부 Agent (D1 유지)

D1의 뜻은 "모델이 다음 관찰·도구·수리를 고르는 반복을 Kookabug가 소유하지 않는다"이다. 제품 안에 실행기가 있어도, 모델 응답을 해석하지 않는다면 D1과 충돌하지 않는다.

| 구성 요소 | 책임 |
|---|---|
| **`kookabug agent-job`** (설치본 포함, daemon 밖 프로세스) | 외부 Agent CLI를 headless로 띄우고 감독한다: 워크스페이스별 중복 방지, 작업 ID·재시작 시 중복 부작용 방지, 전체 시간 상한, 취소 시 연결된 Kookabug 실행까지 정리, 입력 임대권 존중, 무인 `ask` = `deny`, 자기가 바꾼 지식·그래프로 재트리거되지 않음 |
| **예약 등록 UI** (v1: 수동 실행 + 예약 한 종류) | 대상 워크스페이스, 외부 CLI, 실행 계정·세션 조건(잠긴 세션·포커스·절전), 사용할 기준, 예산, 마지막 결과. 권한이 부족하면 준비 실패로 보고한다 |
| **플레이북** (제품 버전과 함께 배포) | `init` · `followup`(Init 이어 하기, UX2) · `triage` · `repair` · `explore` · `author` · `lint`. 위키에서 자동 생성하지 않는다 |
| **daemon·MCP** | 실행·입력 안전, 구조 검증, 권한 판정, 증거 제공, revision 관리, 지식 연산 적용, 자동 채택 검사 |
| **외부 Agent** | 원본 읽기, 조사 순서, 가설, 탐침 선택, 수리 후보 작성, 테스트 작성, 산문 위키 |

- 예산 중 Kookabug 도구 호출·실행 횟수는 작업 ID로 서비스에서 집계하고 강제한다. 모델 호출 수·토큰·비용은 외부 CLI가 그 정보를 줄 때만 상한을 약속한다.

### MCP 추가 (안)

| 툴셋 | 도구 |
|---|---|
| `knowledge` (새로 추가) | `kb_knowledge_search`·`kb_knowledge_get`(조회), `kb_knowledge_apply`(제한 연산 묶음, 기준 revision 필수), `kb_wiki_write`(산문 페이지, revision 대조) |
| `cases` (새로 추가) | `kb_case_get`·`kb_case_list`(조회), `kb_case_open`·`kb_case_update`(변경), `kb_triage_signals`(조회: 가림 처리된 증거와 비교 불가 사유를 모은다. 원인을 판정하지 않는다), `kb_evidence_pin`(실행을 증거 묶음으로 고정) |
| `run` (확장) | `kb_run_start`에 `basis: team|working` 추가(`kb_run_compare`의 기준 실행 `baseline`과 헷갈리지 않게 `basis`). 재실행은 기존 `kb_run_start`로 한다("현재 그래프 재실행"과 "옛 스냅샷 재생"을 섞지 않는다) |
| `core` (UX2) | `kb_source_list`·`kb_source_read`(조회: 등록된 원본만 읽기. UX3부터 읽기 허용 폴더 `kind: read_root`·`read:<…>`(자동 포함은 `read:game`)도 같은 도구·경계·가림으로 — 그 파일은 `source` 근거가 아니다) |
| `cases` (UX2) | `kb_setting_propose`(작업 연결 전용. 허용 목록 키의 설정 바꾸기 **제안**만 — 적용은 사람) |
| 사람 전용 | 치트 채택, 자동 채택 정책 변경, 팀 기준 채택·되돌리기, 설정 제안 수락(D6와 같이 에이전트 연결이면 판정 전에 거부) |

권한 프리셋은 두 개를 추가한다.

- `curator`: 지식·사건 쓰기, 실행, control `ask`
- `qa_runner`: 무인 실행용. 임의 control 입력과 그래프 편집 없이, 채택된 테스트·치트만 실행한다

## 12. 사람에게 보이는 것

- **보고함**(앱): **작업마다 하나씩 쌓인다**(사용자 결정). 한 보고 안의 항목은 같은 원인끼리 묶는다. 버그 보고의 목적지는 v1에서 앱 보고함과 `wiki/reports/`뿐이다. Jira 같은 이슈 트래커 연동은 나중에 **플러그인**으로 제공한다(보고함 항목을 내보내는 확장 지점만 v1에 남긴다).
  - 자동 채택한 수리(되돌리기 한 번)
  - 작업 기준에만 있는 변경(묶음 수락·거절)
  - 회귀 의심(재현 단계·증거 묶음·관련 주장)
  - 판단 불가(필요한 추가 정보, "사람만 줄 수 있음"이 표시된 것만 질문으로 올린다). 질문은 묶음 아래 "답 보내기" 하나로 글을 넣은 것 전부를 보낸다(UX2)
  - 치트 후보
  - 설정 바꾸기 제안(UX2, `setting_change`): 현재 값 → 제안 값, 수락·거절. 키는 마법사가 쓰는 사람 설정(게임 제목·실행 파일·인자·작업 폴더, 원본 추가, 읽기 허용 폴더 추가(UX3 `agent.read_roots.add`, 이 PC), 금지 동작 추가, 치트 분류 추가)뿐. 수락은 마법사 그 단계와 같은 검사·저장이고 제안 뒤 그 키가 바뀌었으면(현재 값 해시 비교) 충돌로 적용하지 않는다. **팀 보고(`knowledge/reports/`)에는 제안 ID·키·이유(쓰기 직전 재검사)·근거 질문만** 싣고, 값·현재 값은 이 PC `.kookabug/jobs/<작업>/proposals.json`에만 둔다(현재 값에 비밀값이 있으면 원문 대신 해시만, 화면은 "[가림]"). 그 파일이 없는 PC(다른 PC가 만든 보고)는 값을 보이지 못하고 거절만 할 수 있다
  - Init·이어 하기 보고에는 "이어서 진행"(UX2): 무인 작업 중이면 꺼지고, 답하지 않은 질문이 있어도 누를 수 있다
- 사람이 아무것도 하지 않아도 Agent는 작업 기준으로 계속 진행한다. 사람의 응답은 **선택**이고 차단 조건이 아니다.
- 위키 뷰어는 v1에서 따로 만들지 않는다. 렌더된 마크다운을 기존 탐색기로 연다.

## 13. 첫 프로젝트 설정 마법사

핵심 설정은 처음 프로젝트를 만들거나 열 때 **단계별로** 정한다. 한 단계가 끝나야 다음으로 넘어간다. [[UX 시안 v0.1]] "첫 실행 흐름"(Setup0~7, Aside 온보딩 레이아웃: 왼쪽 설명·입력, 오른쪽 그림, 아래 이전·진행 점·다음)을 확장한다. Aside가 마지막 단계에서 "첫 작업 시작"으로 바로 일을 시키듯, 마지막 단계는 **Agent로 Init 시작**이다.

| 단계 | 화면 | 정하는 것 | 저장 위치 | 필수 | 완료 조건 |
|---|---|---|---|---|---|
| 0 | 시작 | 새 프로젝트 / 기존 프로젝트 열기 | — | | |
| 1 | 프로젝트 만들기 | 이름, 위치, Git 여부. 오른쪽에 폴더 구조(`knowledge/`·`wiki/` 포함) | 폴더 | ● | 폴더 생성 |
| 2 | 게임 연결 | 실행 파일과 인자 또는 떠 있는 창, 기준 해상도. 오른쪽에 실시간 캡처 | 이 PC(`local.json`), 해상도는 팀 | ● | 창을 한 번 잡음 |
| 3 | 환경 점검 | 캡처·OCR·DPI·입력 전달·창 모드 시험 | — | ● | 시험이 끝남(경고가 있어도 진행, 완료 요약에 남김) |
| 4 | 테스트 계정 | 비밀값 키·아이디·비밀번호 | Windows 자격 증명 | 선택 | 저장 또는 건너뛰기 |
| 5 | **Agent** | 감지한 Agent CLI / 직접 입력 / API 키(판단 노드 전용, Init·조사·수리는 못 한다고 표시), 기본 Agent, 권한 프리셋(마법사에는 읽기 전용·그래프 작성·지식 관리(`curator`, 추천)·전체만. 나머지는 환경설정) | 사용자 설정 | 선택 | **연결 시험 성공** 또는 건너뛰기 |
| 6 | **프로젝트 정보 원본** | 코드 폴더, 데이터·문자열 테이블, 기획 문서, 패치 노트, QA 시트(경로·URL). 항목마다 읽기 확인 | 팀(`kookabug.json#sources`), PC마다 다른 경로는 `local.json` | 선택 | 입력한 항목의 읽기 확인이 끝남 또는 건너뛰기. **읽지 못한 항목은 경고로 남기고 진행**하며, Init이 미지수로 기록한다 |
| 7 | **자동화 정책** | 자동 수리(기본 **켬**, 범위 `tests/` 전체), 금지 동작(사람이 쓰는 목록: 문구·화면·target. **제품 기본값 없음**, "결제"·"캐릭터 삭제" 같은 예시는 입력 안내로만 보여 주고 비어 있으면 완료 요약에 경고), 작업 예산 기본값(작업 하나에 **60분·실행 30회**), 치트 사용 허용 여부(분류는 나중에 직접 만듦, 기본 분류 없음) | 팀(`kookabug.json`) | ● | 기본값 확인(바꾸지 않아도 "다음"으로 확정) |
| 8 | 기록 정책 | 스크린샷, 영상(끔/실패만/항상), 보관 기간 | 팀 | ● | 기본값 확인 |
| 9 | 완료 | 설정 요약, 경고, 건너뛴 단계. 처음 할 일: **Agent로 Init 시작**(Agent 연결 시 기본 버튼) / 녹화 / 빈 에디터. Agent를 건너뛰었으면 Init 항목을 끄고 "Agent를 연결하면 쓸 수 있어요·지금 연결"을 보여 주며 녹화를 기본으로 고른다 | — | | |

- (2026-11-13 UX5 — [[설정·Init 간소화 v0]] 3·4절) **첫 실행 흐름은 0·1·2·3·5·6·9**다. 4 계정·7 자동화 정책·8 기록은 빼고 지금 기본값으로 저장한다(없는 블록만, **금지 동작 기본값은 빈 목록** — 경고 아님). 그 화면들은 설정 도우미에서 하나씩 연다. 3 점검은 모두 통과하면 화면 없이 넘어가고, 5 Agent는 사용자 설정에 기본 Agent가 있으면(자동 연결, 권한은 추천 `curator`를 같은 규칙으로 저장) 넘어간다. 6은 "나중에". 9는 "Init 시작"이 주 단추, 녹화는 보조 링크. 짧은 마법사도 계정을 묻지 않는다(2·3·5). 계정은 접속 경로 단계의 보고함 질문 카드 "테스트 계정 등록"(4단계 화면, 가린 입력 → 주 프로세스가 `kookabug secret set` 표준 입력으로만 넘김)으로 받는다.
- **필수 단계는 완료 조건을 채워야 "다음"이 켜진다.** 선택 단계에는 "건너뛰기" 버튼이 따로 있다. 건너뛴 단계는 완료 화면과 설정 화면의 "설정 도우미"에 남고, 언제든 그 단계만 다시 연다.
- 단계마다 **저장 위치 배지**(팀 · 이 PC · 사용자 · Windows 자격 증명)를 보여 준다. 팀원에게 공유되는 설정인지 알 수 있게 하기 위해서다.
- 중간에 닫으면 진행 단계를 기억하고, 다시 열면 이어서 한다.
- **기존 프로젝트를 처음 여는 경우**(팀원이 저장소를 받음): 팀 설정(6~8)은 이미 있으므로, 이 PC·사용자 단계 중 빈 것만 짧은 마법사로 보여 준다(2 게임 경로, 3 점검, 4 계정, 5 Agent).
- **Agent 설정은 마법사 5단계로 합친다.** 2026-11-09에 추가한 "에이전트 첫 설정 대화 상자"(UX 시안 M7 표의 5 에이전트 패널)는 독립 대화 상자가 아니라 마법사 5단계만 띄우는 형태로 바꾼다. Agent 패널의 "설정 도우미 열기"도 같은 화면을 연다.
- 7단계의 금지 동작은 **정책 층**(사람만 씀)이다. Agent 탐색·제어는 클릭 위치에 금지 문구·target이 보이면 daemon이 거부한다(지금 `AGENTS.md` 한 줄 약속을 도구 강제로 바꾼다).
- 9단계의 "Agent로 Init 시작"은 `kookabug agent-job`으로 Init 플레이북을 실행하고, 결과는 보고함에 쌓인다. 보고함 "이어서 진행"(UX2)도 같은 경로로 `followup`을 실행한다(렌더러가 띄울 수 있는 플레이북은 `init`·`followup`뿐).
- (2026-11-12 UX3) 6단계 원본 칸 아래 **"Agent가 읽어도 되는 폴더"** 묶음: 여러 줄(+ 추가·찾아보기·−), 고칠 수 없는 자동 포함 줄("게임 실행 파일 폴더(자동)" — 실효 `game.executable` 폴더, 실효 `game.cwd`가 다르면 그 줄도), 설명 "여기 넣은 폴더 아래 파일은 Agent(외부 AI 서비스)에게 보일 수 있어요. 비밀값은 가리지만 민감한 폴더는 넣지 마세요." 저장은 이 PC `local.json` `settings."agent.read_roots"`(사람 전용 `local.settings.set`, 같은 revision 대조)이고 허용하지 않는 폴더는 거부 이유를 그대로 보인다. 자동 포함 폴더가 허용하지 않는 폴더면 빼고 경고한다.
- (2026-11-11 사람 첫 툴 테스트 UX1) 2단계 "실행 파일로 띄우기"는 "띄우기"로 실제로 띄우고(`app.launch`, 인자 칸은 Windows `CommandLineToArgvW` 규칙, 고친 칸의 키만 쓴다 — 작업 폴더는 실행 파일 칸을 고쳤을 때만 그 폴더로 바꾼다) 그 창이 뜨면 자동으로 한 번 잡는다(120초 상한). 새로 띄우기는 사람 연결도 무인 작업·검증 세션 중이면 거부한다(`job_active`·`verification_active`). 6단계 원본은 칸마다 여러 줄(첫 줄 = 칸 ID, 더한 줄 = `<칸>_<무작위 6자 hex>`, 예전 `_2`도 읽음). 기본 Agent가 있으면 프로젝트를 연 뒤 Agent 패널이 한 번 자동 연결한다(사람이 끊었거나 무인 작업 중이면 안 함). 보고함에서 진행 중 작업을 열면 활동 목록(Agent가 부른 `kb_*` 도구·`agent.log` 꼬리, `jobs.activity`)이 보인다. 활동 대상은 쓰기 전 `agent.log`와 같은 가림 대상으로 검사해(원문·`+`→공백·경로 구분자 통일 표현) 걸리면 `[가림]`, 퍼센트 인코딩(`%`)이나 NFKC로 바뀌는 글자(전각 등)가 있거나 가림 값을 못 모으거나 그 작업의 토큰 원문이 이미 없으면(끝난 작업) 비운다. 진행 중인 일은 공통 스피너(200ms 지연)로 보인다.
- 시안 초안: [[UX 시안 v0.1]] 폴더의 `Wizard5Agent`·`Wizard6Sources`·`Wizard7Automation`·`Wizard9Init`·`Wizard9NoAgent`(캔버스 10번 줄). 1단계(폴더 구조에 `knowledge/`·`wiki/`)와 8단계(번호만)는 기존 시안을 고친다.

### 완료 시나리오 (둘 다 통과해야 한다)

- **정상 수리**: SampleRPG 상점의 구매 버튼 위치가 바뀌었다. 구매 결과는 그대로다. Agent가 사건을 열어 `ui_change`를 지지한다. locator를 수리하고, 원래 금액·아이템 검증 노드가 실행·통과하는 것을 확인하고, 음성 대조와 영향 테스트를 통과한다. 결과는 자동 채택되고 위키와 보고서가 갱신된다.
- **버그 은폐 방지**: 구매 버튼이 실제로 사라졌다. Agent는 다른 버튼이나 치트로 원래 테스트를 통과 처리하지 않는다. 회귀 의심 사건과 증거 묶음을 남기고 다른 작업을 계속한다.

## M8 구현 반영 (2026-11-10)

M8에서 정한 것만 한 줄씩. 실행·프로세스·RPC 쪽은 [[구현 계획 v0]] "M8 구현 반영", 파일 자리는 [[워크스페이스 구조]].

**6장 지식 형식·연산**
- `source` 근거는 서비스가 확인한다: 실경로로 정규화해 hash를 직접 계산(Agent hash와 다르면 `basis_hash_mismatch`), 원본 폴더 안이라도 워크스페이스 파생 경로는 정규화 전 조각·링크 사슬의 각 단계까지 보고 거부(`basis_derived`). URL 원본은 `verified: false`이고 그것만으로 `expected`를 `supported`로 못 올린다
- 근거의 `seen_at`은 Agent가 준 값이 아니라 서비스가 확인한 시각으로 채운다(사건 신호 "원본 해시 변화"가 Agent 값에 휘둘리지 않게)
- Agent의 기존 `expected` 주장 `revise`·`supersede`·`set_status`·`mark_conflicted`와 Agent 요청이 일으킨 의미 충돌은 `knowledge/working/claims/<기능>.json`(`kookabug.working-claims/0`)에 쌓이고, 보고가 가리킨 작업 rev가 지금과 같을 때만 수락으로 팀에 간다
- 지난 작업 rev는 덧씌움 `history`에 남고, 수락·거절하면 덧씌움 항목이 빠진다(수락 내용은 팀 현재 주장으로 반영하고, 기존 팀 주장은 팀 history로). 응답의 rev·basis는 무변경 연산도 실제 저장 기준(작업 덧씌움에 있으면 `working`과 작업 rev)이다
- 거부된 연산은 지식·위키 파일에 아무것도 쓰지 않지만 감사 이력·요청 기록에는 남는다. 글자 검사 거부와 저장할 수 없는 값(범위 밖 숫자 등)의 형식 거부는 요청 기록·digest 없이 남고, 걸린 요청 ID·주체는 값과 무관한 임의 식별자로 쓴다
- 글자 검사 대상은 연산의 글자·키·숫자(`json.dumps`·`canonical_dumps` 두 표현)·`request_id`·주체 필드이고 digest보다 먼저 본다. 오류 위치는 스키마가 정한 필드 이름·배열 번호만(나머지는 `<key#n>`). 분기(`oneOf`·`anyOf`)는 판별자로 고르고, 못 고르면 모든 후보가 정한 키만 쓴다
- 증거 manifest도 마지막에 글자 검사: 걸린 필드는 값 없이 빼고 `omitted`에 위치만, 필수 필드면 고정 거부
- 사건 시그니처의 그래프 해시 = 루트 sha + 스냅샷 폐포 digest. 열린 사건(open·needs_info·watching)에만 붙는다. 증상 종류는 실패 노드 타입으로 정한다. Agent `kb_case_update`는 title·state(open·needs_info·watching)·hypotheses·actions·needs·recheck·links만
- 정체 감지: 같은 작업·같은 테스트의 마지막 3번이 같은 시그니처로 실패했고 실효 재료(루트 sha·덧씌움 폐포 digest·프로필·원본 해시·실효 설정 digest·요청 기한)도 같을 때만 `stalled_repeat`. 재료를 못 구하면 거부하지 않는다

**7장 두 기준·자동 채택**
- 작업 기준 실행의 덧씌움 = active이고 stale 아닌 변경 전부, 같은 경로면 이 작업 → 이 Agent → 나중 변경 순. 작업이 요청한 채택 검증 실행도 `run.json.job`에 그 작업 ID(재트리거 입력 아님)
- 조건 2: 바뀐 필드는 `image`·`search.region`(줄이기·옮기기)·`click`·`recorded`뿐. 넓힘은 알려진 모든 프레임 크기(팀·후보 녹화 크기, 원래 실패가 관측한 창 크기)에서 픽셀 넓이로 비교해 1px이라도 넓으면 거부, 크기를 하나도 모르면 정규 값으로 비교. 후보 target을 읽는 노드의 출력은 입력 조작 핀으로만 흘러야 하고, 팀 전체 그래프의 `$link` 판정 사용까지 본다(`target_used_for_judgment`). 사람이 쓴 경로(그래프·target·manifest·채택 기록·작업 변경·요청 인자)의 같은 파일 비교와 파일 종류 판별은 `path_key`(구분자·casefold, 후보 경로의 철자가 디스크 실제 철자와 다르거나 후보에 같은 파일 키가 둘이면 `path_alias`), 같은 함수 산출끼리의 재확인 비교는 글자 그대로(철자가 바뀌면 다르다고 봄)
- dry 스냅샷 캐시(`.kookabug/cache/adopt`)가 쓰기 경계 밖이면 조건 1 `path_outside_workspace`(채택을 시작할 수 없는 환경). 캐시 정리는 UUID 이름 + 소유 표시 파일이 있는 항목만
- Agent의 그래프 diff는 조건 2(`not_locator_only`)에서 막힌다. `oracle_changed`(조건 3)는 원래 실패 뒤 사람이 팀 판정 의존성을 바꾼 경우다
- 조건 3: 판정 의존성 = 판정 노드 입력 + 추적 가능 생산자(`$link` 허용 목록)를 거친 target·PNG·`$setting`. 밖이면(`$secret`·OCR 글자·플러그인 판정 노드 등) `oracle_untraceable`로 자동 채택하지 않는다. 원래 의존성 sha는 사건 원래 실행의 스냅샷에서 읽는다
- 조건 4: 판정 노드가 실행됐다가 실패하면 `oracle_failed`, 하나도 실행되지 않으면 `oracle_not_run`. Agent는 검증 근거 실행을 지정할 수 없다(입력 칸 없음)
- 조건 5: 원래 화면(옛 locator가 찾는 화면 지도 이미지)은 음성 프레임에서 뺀다. `neg-*` 묶음은 `negative{targets, frames}`·출처가 있고 경로가 정규형일 때만 쓰고, 이 target에 묶인 묶음이 쓸 수 없으면 `no_negative_control`
- 게시 잠금 안에서 정책·판정 의존성·주장 rev·참조 스캔·영향 테스트·음성 프레임을 다시 계산해 다르면 조건 8 `revision_conflict`. 검증 실행에도 금지 동작 판정, 검증 사이 다른 입력이 들면 무효(`input_between_verifications`), 취소된 채택은 감사 이력 `adopt_cancelled`
- 되돌리기는 `kind: revert` 새 기록 + 원 기록 `reverted`, 사건은 `open`으로. 묶음 수락(`kind: accept`)도 파일은 한 번 되돌릴 수 있다. 채택 거부·사건 닫기 거부는 감사 이력에 남지 않는다

**금지 동작 (13장 7단계 정책의 강제)**
- 적용 대상은 Agent 주체 실행과 무인 실행(자동 채택 검증 실행 포함) 전부이고 기준(team·working)과 무관하다. 일반 사람 대화형 실행만 제외(공용 진입점 `guard_options` 한 곳에서 정함)
- Agent 입력(클릭·키·문자)은 금지 문구·target·화면이 화면 **어디든** 보이면 거부(`forbidden_visible{kind, value}`), 화면 식별·OCR·target 조회·프레임 실패는 `forbidden_unverifiable`, 목록이 비면 생략. 판정 함수는 core `forbidden.judge` 하나이고 금지 목록은 실행 시작 때 고정. 감독자의 키 떼기·입력 복구는 이 검사를 거치지 않는다
- 보호 화면은 확인 못 함이다. 단 비밀값 칸 상자를 모두 아는 `secret_field` 보호는 그 칸만 가린 사본으로 읽는다
- 정책을 못 읽거나 금지 target·화면 파일을 못 읽으면 Agent 입력·실행 시작·target 쓰기·자동 채택 게시를 거부한다. Agent는 금지 판정이 읽는 파일을 실경로 기준으로 쓰지 못한다

**10장 `qa`·치트**
- 실행 노드는 `core.qa.cheat`(config `cheat`·`args`). `cheats.allow[].max_calls` 필수이고 루트 실행 전체에서 센다. 서브그래프 `qa`는 `cheats`만, 상위 허용을 줄이는 쪽(교집합)으로만. 치트 구현 안 치트 노드는 거부
- 채택 digest = 정의 필드 + 실행 의존성(그래프·target·이미지·화면) 폐포 바이트 + 노드 구현 revision(코어 소스 sha·플러그인 잠금). 폐포는 위치와 무관하고, 빼는 것은 로더가 지식 형식으로 읽은 메타데이터 파일(치트 정의·주장)뿐이며 그것도 실행 의존성으로 쓰이면 다시 넣는다. 구현 노드는 허용 목록만, `knowledge/` 아래 의존성·`$setting`·`$secret`·미해결 참조·중첩이면 채택·실행 거부. 채택은 rev를 올리지 않는다. Kookabug를 올리면 다시 채택한다
- 거부 코드: 채택·digest·동적 의존성 = `cheat_not_adopted`, 그 밖 = `cheat_denied`. 실행 스냅샷이 원본에서 본 구현 문제를 함께 고정한다

**8·11장 작업·플레이북**
- 플레이북 `triage`·`repair`·`explore`·`init`·`author`의 허용 툴셋에 control이 있다. 작업 안 직접 입력은 탐침용이고, 사건을 닫거나 채택 근거가 되지 못한다(검증은 Kookabug가 새로 띄운 게임에서)
- 예약 등록 UI는 M9. M8은 CLI `kookabug agent-job schedule install|remove|show`

**12장 보고함**
- 보고 항목은 작업의 구조화 기록에서 만든다. `revisions.claims`에 생성 시점 주장 rev를 담고 렌더는 그 값만 쓴다. 끝난 보고는 덮지 않고 `report.decide`가 결정만 더해(한 filetx 거래) 다시 렌더한다. 통과한 연결 시험 보고는 목록에서 숨긴다

**13장 마법사**
- 진입점: 시작 화면 "시작하기"(새 프로젝트)·"이미 있는 프로젝트 열기"(→ 짧은 마법사), 환경설정 "설정 도우미", 에이전트 패널 "설정 도우미 열기"(5단계만), 상태 바 감시(자동 띄우기 — 화면은 늘 하나)
- 짧은 마법사는 이 PC에 진행(`.kookabug/wizard.json`)이 없고 팀 첫 설정을 마친(`wiki/index.md`) 프로젝트에서만 자동으로 뜬다
- 짧은 마법사 이어서도 `team_setup`이 있어야 한다. 단계 하나만 열었다 닫은 기록으로는 짧은 마법사를 띄우지 않는다(합치기 R11)
- 짧은 마법사 조건이 음성이고 사용자 설정에 에이전트가 없으면 5단계만(`only`) 한 번 띄운다. "한 번" = `wizard.json`에 5단계 완료·건너뜀이 없음. `only` 화면을 닫으면 그 선택 단계는 건너뜀으로 남는다(합치기 2)
- 5단계 연결 시험은 본체 CLI(`cli_path`)만 있어도 한다. ACP 어댑터는 패널 연결에만 필요하다. `only` 모드 5단계는 "저장됨"이면 끝나고(저장 / 저장하고 연결 — 패널 세션 시작) 시험은 선택이다. 새 프로젝트·짧은 마법사의 5단계는 시험 통과 또는 건너뛰기
- 5단계에서 고른 Agent가 곧 기본 Agent다(따로 고르는 칸 없음). 권한 프리셋은 새 프로젝트이면서 사용자 프리셋이 없을 때만 `curator` 추천을 저장하고, 그 밖(`only`·짧은 마법사·이미 프리셋 있음)은 지금 실제 프리셋을 보이고 사람이 바꿨을 때만 저장한다. 프리셋 저장(5단계·패널)도 화면이 읽은 revision 기준이며 같은 흐름의 자기 agents 저장 revision만 이어 받는다(합치기 3)
- 5단계는 에이전트 저장·진행("다음"·"저장") 중과 충돌 중에 줄·직접 입력·프리셋 고르기를 잠근다(연결 시험 중 고르기는 된다). 진행은 기본 Agent를 쓰지 않고 확인만 한다: 이 앱이 자기 저장으로 남긴 기본이 지금 선택이고 파일 revision이 그대로일 때만 끝난다. 에이전트 저장 충돌도 "다시 읽기" 전까지 막고, 재연결 같은 다른 읽기는 저장 기준을 바꾸지 않는다(합치기 5)
- 4단계는 값을 받지 않는다: 계정 값은 녹화 중 비밀번호 칸 → "비밀값으로 저장"(M4)으로 만들고, 마법사는 키 목록·안내만
- 단계 저장은 화면을 채울 때 읽은 sha·revision으로 한다(충돌이면 "다시 읽기" 안내). 6단계는 사람이 바꾼 칸만 쓰고, 같은 ID 원본이 여럿이면 그 칸을 저장하지 않는다
- 연결 시험 결과는 그 화면 동안만 기억한다. 5단계 뒤 닫았다 다시 열면 9단계 Init은 "지금 연결"로 다시 시험해야 켜진다

**14장 완료 시나리오 (예제 상점)**
- 예제 상점은 예제 게임과 다른 패키지·창(`sample_shop`, 렌더 PNG를 창·헤드리스가 같이 씀). 시나리오는 상점에서 바로 시작한다. 구매 target과 무관한 계속 진행 테스트는 `close_shop`
- `frames/shop/frames.snapshot.json`에 렌더 관련 소스 sha를 둔다. `gen_shop_scenario --check`는 OS와 무관하게 소스 sha·PNG·target·표를 보고, 픽셀 대조는 같은 Windows·글꼴일 때만 한다
- 예제 `give_gold`는 미채택으로 커밋한다(digest가 구현 revision을 담음). 검사·사람이 시작 때 사람 경로로 채택한다
- 은폐 시도 ⑦(콘솔 직접 입력)은 탐침 입력은 실행되지만 사건 닫기(`case_resolution_reserved`)·채택 근거는 막힌다. ① 판매 단추 자르기는 조건 4 `oracle_failed`, ④ 기대값 patch는 조건 2 `not_locator_only`
