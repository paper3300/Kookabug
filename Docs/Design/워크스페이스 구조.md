## 원칙

- **게임 하나에 워크스페이스 하나**. 빌드·플랫폼 차이는 설정 프로필로 다룬다
- 툴 레포와 워크스페이스는 분리한다 (확정 사항). 워크스페이스는 사용자가 자기 Git 저장소로 관리한다
- 최상위는 **종류별**로 나누고, 그 안은 **기능별** 하위 폴더를 자유롭게 만든다
- 커밋할 것과 Git에서 뺄 것을 처음부터 나눈다

## 폴더

```
workspace/
├─ kookabug.json              팀 공용 설정 (커밋)
├─ kookabug.lock              플러그인 버전 잠금 (커밋)
├─ AGENTS.md                  에이전트용 안내 (자동 생성, 커밋)
├─ .gitignore                 runs/, .kookabug/ 제외 (자동 생성)
├─ tests/                     테스트 그래프
│  ├─ inventory/open.graph.json
│  └─ shop/buy_potion.graph.json
├─ subgraphs/                 서브그래프
│  └─ enter_world.graph.json
├─ targets/                   찾기 대상과 이미지
│  ├─ login/login_button.target.json
│  └─ login/login_button.png
├─ screens/                   화면 지도
│  ├─ world_field.screen.json
│  └─ _explored/              Agent 탐색 결과 (사람 확인 전)
├─ runs/                      실행 기록 (Git 제외)
└─ .kookabug/                 개인 설정·캐시 (Git 제외)
   ├─ local.json
   ├─ daemon.lock             daemon이 살아 있는 동안 쥐는 잠금 파일
   ├─ session.json            daemon 접속 정보 (포트·토큰, daemon이 쓰고 끝날 때 지움)
   ├─ logs/                   daemon 로그 (daemon-<시각>-<PID>.log, 최근 20개)
   ├─ editor-images.json      에디터 소유 기록: target 편집기가 직접 만든 이미지 (이것만 자동 정리)
   ├─ breakpoints.json        디버거 브레이크포인트 (M3, daemon이 원자적으로 씀)
   ├─ cache/editor/           편집기 정지 화면 PNG (daemon 시작 때 비움, 200 MiB 넘으면 오래된 것부터)
   └─ cache/runs/             끝난 실행의 색인·비교 캐시 <run_id>.index.json 등 (M3, 지워도 다시 만듦)
```

- **`cache/runs/`** (M3): 기록 뷰어가 읽는 실행 색인(스텝 트리·반복 회차 요약·실패 사슬·노드별 통계·스텝별 이벤트 위치)을 끝난 실행마다 하나씩 둔다. daemon이 `events.jsonl`을 한 번 훑어 만들고(코어 `record/index.py`), 그 파일의 크기·수정 시각이 같으면 다시 만들지 않는다. 진행 중 실행의 색인은 메모리에만 있고 실행이 끝나면 여기로 옮긴다. 캐시일 뿐이라 지우거나 틀려도 다음 읽기가 다시 만든다. 실행 폴더를 지우면(보관 정리) 같이 지워도 된다

- **`breakpoints.json`** (M3): `{format: "kookabug.breakpoints/0", breakpoints: [{graph, node}]}`(`breakpoints.schema.json`). `graph`는 워크스페이스 루트 기준 그래프 경로, `node`는 노드 ID다. 사람마다 다른 디버깅 상태라 개인 파일이다(팀과 공유하지 않는다). daemon만 쓰고(목록 전체를 정렬·중복 제거해 같은 폴더 임시 파일 + replace), 앱은 `debug.breakpoints.get/set`으로 읽고 바꾼다. 읽을 수 없거나 형식이 틀린 파일은 빈 목록으로 본다. 사람이 앱에서 시작한 실행에만 쓰이고, CLI·에이전트 실행은 이 파일을 보지 않는다([[그래프 JSON 스키마 v0]] 6장 "디버거로 멈췄다 재개")

| 폴더 | 무엇을 | 규칙 |
|---|---|---|
| `tests/` | `kind: "test"` 그래프 | 하위 폴더는 기능별로 자유 |
| `subgraphs/` | `kind: "subgraph"` 그래프 | 테스트에서 `config.graph`로 참조 |
| `targets/` | `*.target.json` + 이미지 | 이미지는 target 파일 옆에 둔다. target의 `image`는 그 파일 기준 상대 경로. target 편집기는 이 폴더 아래에만 저장하고, 사용자가 넣은 PNG는 지우지 않는다([[그래프 JSON 스키마 v0]] 4장 "편집기 저장") |
| `screens/` | `*.screen.json` (화면 판정 조건, [[그래프 JSON 스키마 v0]] 4장) | 화면 ID는 파일 이름 줄기이고 하위 폴더는 자유. 같은 ID가 둘이면 그 ID를 출구 `screen`으로 가리키는 그래프의 검증과 `kookabug screen test <ID>`에서 오류(가리키지 않는 중복은 검증에서 보지 않는다). `_explored/`는 판정에 쓰지 않는다. 화면 간 이동은 서브그래프 출구의 `screen`과 실행 기록, Agent 탐색 결과에서 모아 뷰어가 만든다 |
| `runs/` | 실행 폴더 | Git 제외. 보관 정책으로 정리 |
| `.kookabug/` | 개인 설정, 캐시, 인덱스, daemon 잠금·접속 정보·로그 | Git 제외. `session.json`에는 daemon 토큰이 있으므로 공유하지 않는다. 에디터는 이 폴더 안을 열거나 보여 주지 않는다 |

- 파일 이름: 테스트와 서브그래프 모두 `*.graph.json`. 구분은 파일 안의 `kind`로 한다. 폴더와 `kind`가 어긋나면(예: `tests/`에 서브그래프) 실행 전 검증에서 경고한다
- 모든 참조 경로는 워크스페이스 루트 기준이다. 단, target의 `image`만 target 파일 기준이다

## 설정

| 파일 | 커밋 | 담는 것 |
|---|---|---|
| `kookabug.json` | O | 팀 공용 설정, 프로필, 기록 정책, 보관 정책, 에이전트 권한 상한 |
| `.kookabug/local.json` | X | 사람마다 다른 값 (게임 실행 경로, 모니터 등), 이 워크스페이스의 에이전트 권한 |
| `%APPDATA%\Kookabug\settings.json` | 워크스페이스 밖 | 사용자 설정: 모든 워크스페이스에 쓰는 에이전트 권한 (`format: "kookabug.user-settings/0"`) |

`$setting` 값을 찾는 순서: 실행 옵션(CLI) → `.kookabug/local.json` → 선택한 프로필 → `kookabug.json` 기본값. 없으면 실행 전 검증 오류.

위에서부터 **처음으로 그 키를 가진 계층의 값**을 쓴다 (계층을 병합하지 않는다). 그 값이 `null`이면 아래 계층으로 내려가지 않고 실행 전 검증 오류다 (`local.json`에 적은 `null`도 마찬가지).

```json
{
  "format": "kookabug.workspace/0",
  "profiles": {
    "dev": {
      "settings": {
        "game.server": "Server 1"
      }
    },
    "qa": {
      "settings": {
        "game.server": "QA Server"
      }
    }
  },
  "record": {
    "screenshots": "on",
    "video": "failed_only"
  },
  "retention": {
    "failed_days": 60,
    "keep_last": 50,
    "passed_days": 14
  },
  "run": {
    "deadline_ms": 600000
  },
  "settings": {
    "game.executable": null,
    "game.server": "Server 1"
  }
}
```

- `run`은 실행 조건 기본값(시간은 밀리초)이다. `deadline_ms` 실행 전체 기한(없으면 30분, CLI `--deadline-ms`가 우선), `worker_cancel_grace_ms` 취소한 워커 노드를 기다리는 시간(2000), `worker_start_timeout_ms` 워커 시작 기한(30000), `shutdown_grace_ms` 취소·마무리를 시작한 runner를 기다리는 시간(5000, 넘으면 감독자가 끝낸다. 4000보다 짧으면 runner가 영상 마무리를 기다리는 시간을 그만큼 줄여 기록을 먼저 끝낸다 — 인코더가 늦으면 그 실행 영상을 잃는다), `capture_timeout_ms` 캡처·찾기·OCR 호출 하나의 설정 기한(2000, 넘으면 `capture_timeout`, CLI `--capture-timeout-ms`가 우선), `frame_budget_mib` 프레임 저장소 바이트 예산(512), `frame_output_refs` 스텝 출력으로 나간 프레임을 남기는 개수(32)
- `ocr`은 OCR 엔진과 그 설정이다. `engine`(M1은 `rapidocr` 하나, 기본), `det`(검출 크기 설정 `limit_side_len`·`max_side_len`·`single_max_pixels`·`tile_side`·`tile_overlap`, 없는 값은 기본값)
- `null`은 "사람마다 `local.json`에 넣어야 하는 값"이다. 비어 있으면 실행 전 검증이 어디에 넣으라고 안내한다
- `record`는 [[그래프 JSON 스키마 v0]] 6장의 워크스페이스 정책이다. 정하지 않으면 `screenshots: on`, `video: failed_only`(성공한 실행의 영상은 지운다). 성공한 실행의 영상도 남기려면 `video: on`
- `record.redact_secrets`(기본 `false`)는 비밀값 가림 스위치다. 기본은 개발 환경 전용 도구로 보고 비밀값을 받은 스텝의 화면·영상과 이벤트·로그의 비밀값 원문을 그대로 남긴다. `true`면 그 스텝의 스크린샷·영상을 남기지 않고 기록의 비밀값을 `***`로 가린다. 실행 기록을 밖으로 넘기는 워크스페이스는 켠다
- 실행 전체 기한(`run.deadline_ms`)은 에디터 실행 툴바의 "기한"으로 그 실행만 바꿀 수 있다 ("기본"이 이 값)

### 에이전트 권한

세 파일 모두 같은 모양의 `permissions`를 둘 수 있다. 판정 대상은 **에이전트**(MCP·`KOOKABUG_AGENT`를 붙인 CLI)이고, 사람이 UI·CLI로 직접 하는 일은 판정하지 않는다. 도구 이름은 [[구현 계획 v0]] 7장 MCP 도구다.

```json
{
  "permissions": {
    "preset": "runner",
    "rules": [
      {
        "rule": "kb_run_start(tests/smoke/*)",
        "verdict": "allow"
      },
      {
        "rule": "kb_input_type",
        "verdict": "deny"
      }
    ],
    "toolsets": {
      "control": "ask"
    }
  }
}
```

- `rule`은 `도구` 또는 `도구(인자 패턴)`. 도구·인자 모두 glob(`*`, `?`)이고 대소문자를 구분한다. 인자는 대표 인자 하나다 (`kb_run_start`는 그래프 경로). 괄호를 생략하면 모든 인자
- 프리셋은 `read_only`·`graph_author`(기본)·`runner`·`full`. 값은 [[구현 계획 v0]] 7장 표
- 판정 순서
  1. 세 계층의 규칙 중 맞는 것: deny > ask > allow
  2. 맞는 규칙이 없으면 툴셋 값 (`local.json` → 사용자 설정). 변경 도구에는 그 값 그대로, 조회 도구는 툴셋을 `deny`로 막았을 때만 막는다
  3. 툴셋 값이 없으면 프리셋 (`local.json` → 사용자 설정 → `graph_author`)
  4. `kookabug.json`의 툴셋 값(없으면 프리셋 값)은 **팀 상한**이다. 위 결과보다 엄격하면 팀 값을 쓴다. `kookabug.json`의 규칙은 1에 들어간다
  5. 사람이 없는 실행(CLI의 에이전트, 무인 MCP)에서 `ask`는 `deny`
- 권한 설정 파일을 읽을 수 없거나(경로가 폴더, 접근 거부 등) `permissions` 형식이 틀리면 에이전트의 요청은 전부 거부한다 (사람은 영향 없음). 사용자 설정·`local.json`은 파일이 없으면 빈 계층이지만, `kookabug.json`이 없으면 거부한다(지워서 팀 상한을 없앨 수 없게). 파일의 다른 부분이 틀려도 `permissions`는 따로 읽는다
- `ask`는 사람이 승인할 때까지 실행하지 않는다

## 비밀값

- 평소: **Windows 자격 증명 관리자**에 저장한다. 키는 `kookabug:<워크스페이스 ID>:<비밀 키>`. 파일에는 남지 않는다
- CI·무인 실행: 환경 변수 `KOOKABUG_SECRET_<키>`로 넣는다 (키의 `.`은 `_`로, 대문자로. 예: `accounts.qa_tester_01` → `KOOKABUG_SECRET_ACCOUNTS_QA_TESTER_01`)
- 찾는 순서: 환경 변수 → 자격 증명 관리자. 없으면 실행 전 검증 오류
- 그래프와 설정에는 키 이름만 들어간다 (`{ "$secret": "accounts.qa_tester_01" }`)

## 플러그인 잠금

`kookabug.lock`에 설치된 플러그인의 ID, 버전, 받은 곳, 해시를 기록한다. 팀원이 같은 버전으로 실행하고, 실행 기록에도 이 내용이 들어간다.

## 실행 기록 보관

- `runs/`는 Git에서 뺀다
- 기본 보관: 최근 50개는 항상 남기고, 통과한 실행은 14일, 실패·오류 실행은 60일 (`kookabug.json`의 `retention`)
- 사람이 고정(핀)한 실행은 지우지 않는다
- 팀 공유는 **번들 내보내기**(실행 폴더 zip)나 이슈 트래커 첨부로 한다

## `AGENTS.md`

워크스페이스를 만들 때 자동으로 만든다. 에이전트가 이 워크스페이스에서 지킬 규칙을 적는다.

- 폴더 규칙과 파일 형식 문서 위치
- 그래프를 고칠 때는 Kookabug MCP 도구를 쓰고, 노드 ID를 바꾸지 말 것
- 실패 분석은 `runs/<실행>/events.jsonl`과 스크린샷부터 볼 것
- 비밀값을 파일에 쓰지 말 것

사용자가 고친 내용은 덮어쓰지 않는다. 툴이 관리하는 구간만 표시해 두고 그 안만 갱신한다.

## 이후 버전

- 여러 게임을 묶는 상위 워크스페이스 (공용 서브그래프 라이브러리 공유)
- 실행 기록을 NAS·클라우드에 모아 보는 팀 저장소

## M3 구현 반영

| 바뀐 것 | 이유 |
|---|---|
| `.kookabug/breakpoints.json`(개인 파일, daemon이 원자적으로 씀, 사람이 앱에서 시작한 실행에만 쓰임) | 브레이크포인트는 사람마다 다른 디버깅 상태라 팀 파일(`kookabug.json`)이나 그래프 파일에 넣으면 커밋에 섞인다. 실행 중 바뀐 목록을 진행 중인 실행에 넣으려면 daemon 한 곳이 들고 있어야 한다 |
| `.kookabug/cache/runs/<run_id>.index.json`: 끝난 실행의 색인 캐시(`events.jsonl` 크기·수정 시각이 같으면 그대로 씀) | 1만 회 반복 실행은 이벤트가 수십만 줄이라 뷰어를 열 때마다, 회차를 넘길 때마다 다시 훑으면 느리다. 실행 폴더는 기록이라 고치지 않으므로 색인은 개인 캐시 폴더에 둔다 |
| 같은 폴더에 `<run_id>.compare.json`(지난 성공과 비교한 마지막 결과, 기준·스텝과 두 실행의 `events.jsonl` 크기·수정 시각이 같으면 그대로 씀)과 `<run_id>.snapshot.json`(스냅샷 파일마다 크기·수정 시각·sha256) | 비교는 화면 차이(이미지 디코드)와 스냅샷 해시(파일 전체 읽기)가 무겁다. 실행 폴더에 쓰지 않고 색인 캐시 옆에 둔다. 예전 실행도 비교되게 runner가 아니라 daemon이 비교할 때 계산한다 |

## M4 구현 반영

| 바뀐 것 | 이유 |
|---|---|
| 자격 증명 관리자 비밀값을 실제로 읽는다(일반 자격 증명 `kookabug:<워크스페이스 ID>:<키>`, 값 UTF-16, 이 PC 보관). 워크스페이스 ID는 `kookabug.json` `id`(UUID)이고 없으면 처음 비밀값을 만들 때(`secrets.create`) 그 한 필드만 넣는다. `id`가 없으면 환경 변수만 찾는다. 앱은 키 목록(값 없음)과 녹화 메모리의 글자로 새 비밀값 만들기만 한다 — 값을 화면·RPC로 받지 않는다 | 설계는 "평소: 자격 증명 관리자"인데 환경 변수만 구현돼 녹화가 고르게 하는 키가 실행에서 풀리지 않았다. 팀 공유 파일의 ID라야 PC마다 같은 키 이름이 된다 |
| `.kookabug/cache/recorder/<세션>/`: 녹화 세션 임시 저장소(붙잡은 화면 PNG, 글자 없는 스텝 기록). 세션이 끝나면 지운다. 녹화 글자는 daemon 메모리에만 있고 세션 끝에 지운다 | 녹화는 키 입력 전체를 다루므로 디스크에 글자를 남기지 않는다. 화면 픽셀은 D3대로 가리지 않되 임시다 |
