# 워크스페이스 구조

- 작성일: 2026-10-29
- 상태: 확정
- 근거: [[결정 현황]], [[그래프 JSON 스키마 v0]]

---

## 원칙

- **게임 하나에 워크스페이스 하나**. 빌드·플랫폼 차이는 설정 프로필로 다룬다
- 툴 레포와 워크스페이스는 분리한다 (확정 사항). 워크스페이스는 사용자가 자기 Git 저장소로 관리한다
- 최상위는 **종류별**로 나누고, 그 안은 **기능별** 하위 폴더를 자유롭게 만든다
- 커밋할 것과 Git에서 뺄 것을 처음부터 나눈다

## 폴더

```
workspace/
├─ kookabug.json              팀 공용 설정 (커밋)
├─ kookabug.lock              플러그인 버전 잠금 (커밋)
├─ AGENTS.md                  에이전트용 안내 (자동 생성, 커밋)
├─ .gitignore                 runs/, .kookabug/ 제외 (자동 생성)
├─ tests/                     테스트 그래프
│  ├─ inventory/open.graph.json
│  └─ shop/buy_potion.graph.json
├─ subgraphs/                 서브그래프
│  └─ enter_world.graph.json
├─ targets/                   찾기 대상과 이미지
│  ├─ login/login_button.target.json
│  └─ login/login_button.png
├─ screens/                   화면 지도
│  ├─ world_field.screen.json
│  └─ _explored/              Agent 탐색 결과 (사람 확인 전)
├─ runs/                      실행 기록 (Git 제외)
└─ .kookabug/                 개인 설정·캐시 (Git 제외)
   └─ local.json
```

| 폴더 | 무엇을 | 규칙 |
|---|---|---|
| `tests/` | `kind: "test"` 그래프 | 하위 폴더는 기능별로 자유 |
| `subgraphs/` | `kind: "subgraph"` 그래프 | 테스트에서 `config.graph`로 참조 |
| `targets/` | `*.target.json` + 이미지 | 이미지는 target 파일 옆에 둔다. target의 `image`는 그 파일 기준 상대 경로 |
| `screens/` | `*.screen.json` (화면 판정 조건) | 화면 간 이동은 서브그래프 출구의 `screen`과 실행 기록, Agent 탐색 결과에서 모아 뷰어가 만든다 |
| `runs/` | 실행 폴더 | Git 제외. 보관 정책으로 정리 |
| `.kookabug/` | 개인 설정, 캐시, 인덱스 | Git 제외 |

- 파일 이름: 테스트와 서브그래프 모두 `*.graph.json`. 구분은 파일 안의 `kind`로 한다. 폴더와 `kind`가 어긋나면(예: `tests/`에 서브그래프) 실행 전 검증에서 경고한다
- 모든 참조 경로는 워크스페이스 루트 기준이다. 단, target의 `image`만 target 파일 기준이다

## 설정

| 파일 | 커밋 | 담는 것 |
|---|---|---|
| `kookabug.json` | O | 팀 공용 설정, 프로필, 기록 정책, 보관 정책 |
| `.kookabug/local.json` | X | 사람마다 다른 값 (게임 실행 경로, 모니터 등) |

`$setting` 값을 찾는 순서: 실행 옵션(CLI) → `.kookabug/local.json` → 선택한 프로필 → `kookabug.json` 기본값. 없으면 실행 전 검증 오류.

위에서부터 **처음으로 그 키를 가진 계층의 값**을 쓴다 (계층을 병합하지 않는다). 그 값이 `null`이면 아래 계층으로 내려가지 않고 실행 전 검증 오류다 (`local.json`에 적은 `null`도 마찬가지).

```json
{
  "format": "kookabug.workspace/0",
  "profiles": {
    "dev": {
      "settings": {
        "game.server": "Server 1"
      }
    },
    "qa": {
      "settings": {
        "game.server": "QA Server"
      }
    }
  },
  "record": {
    "screenshots": "on",
    "video": "failed_only"
  },
  "retention": {
    "failed_days": 60,
    "keep_last": 50,
    "passed_days": 14
  },
  "settings": {
    "game.executable": null,
    "game.server": "Server 1"
  }
}
```

- `null`은 "사람마다 `local.json`에 넣어야 하는 값"이다. 비어 있으면 실행 전 검증이 어디에 넣으라고 안내한다
- `record`는 [[그래프 JSON 스키마 v0]] 6장의 워크스페이스 정책이다

## 비밀값

- 평소: **Windows 자격 증명 관리자**에 저장한다. 키는 `kookabug:<워크스페이스 ID>:<비밀 키>`. 파일에는 남지 않는다
- CI·무인 실행: 환경 변수 `KOOKABUG_SECRET_<키>`로 넣는다 (키의 `.`은 `_`로, 대문자로. 예: `accounts.qa_tester_01` → `KOOKABUG_SECRET_ACCOUNTS_QA_TESTER_01`)
- 찾는 순서: 환경 변수 → 자격 증명 관리자. 없으면 실행 전 검증 오류
- 그래프와 설정에는 키 이름만 들어간다 (`{ "$secret": "accounts.qa_tester_01" }`)

## 플러그인 잠금

`kookabug.lock`에 설치된 플러그인의 ID, 버전, 받은 곳, 해시를 기록한다. 팀원이 같은 버전으로 실행하고, 실행 기록에도 이 내용이 들어간다.

## 실행 기록 보관

- `runs/`는 Git에서 뺀다
- 기본 보관: 최근 50개는 항상 남기고, 통과한 실행은 14일, 실패·오류 실행은 60일 (`kookabug.json`의 `retention`)
- 사람이 고정(핀)한 실행은 지우지 않는다
- 팀 공유는 **번들 내보내기**(실행 폴더 zip)나 이슈 트래커 첨부로 한다

## `AGENTS.md`

워크스페이스를 만들 때 자동으로 만든다. 에이전트가 이 워크스페이스에서 지킬 규칙을 적는다.

- 폴더 규칙과 파일 형식 문서 위치
- 그래프를 고칠 때는 Kookabug MCP 도구를 쓰고, 노드 ID를 바꾸지 말 것
- 실패 분석은 `runs/<실행>/events.jsonl`과 스크린샷부터 볼 것
- 비밀값을 파일에 쓰지 말 것

사용자가 고친 내용은 덮어쓰지 않는다. 툴이 관리하는 구간만 표시해 두고 그 안만 갱신한다.
