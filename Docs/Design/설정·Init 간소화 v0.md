# 설정·Init 간소화 v0 (기획 초안)

- 상태: 초안 (2026-11-12). 사용자 확인 뒤 UX5로 구현한다.
- 출처: `Docs/Brainstorming/2026.11.12 브레인스토밍.excalidraw.md`

## 1. 문제

- 설정 마법사가 화면 10개(0~9단계)이고, 그중 필수가 5개다. Init 뒤에도 질문 답 → 이어 하기가 이어진다. 처음 쓰는 사용자 대부분이 이 구간에서 떠날 가능성이 높다.
- 녹화나 노드 구성을 사람이 직접 하는 일은 드물다. 거의 모든 사용자는 Agent에게 맡긴다.
- 옵션은 있어야 하지만, 처음에 다 정하게 하지 않는다. 쓰다가 필요한 순간에 알게 하고, 그때 정하게 한다.

## 2. 원칙

1. **처음에는 묻지 않는다.** 기본값으로 시작하고, 필요해지는 순간에 묻는다.
2. **필요할 때 묻는 길**은 세 가지다.
   - Agent가 막혔을 때 보고함 질문 카드
   - Agent의 설정 바꾸기 제안(UX2)
   - 설정 화면
3. **Init은 시작할 수 있을 만큼만 한다.** 게임 접속 같은 깊은 구성은 다음 단계로 넘긴다.

## 3. 설정 마법사

| 지금 단계 | 바뀜 | 대신 묻는 때 |
|---|---|---|
| 0 시작 | 유지 (새로 만들기 / 열기) | |
| 1 프로젝트 | 유지 | |
| 2 게임 | 유지 | |
| 3 환경 점검 | 자동으로 돌리고, 통과하면 화면을 건너뜀. 실패할 때만 보임 | |
| 4 테스트 계정 | **삭제** | 접속 경로 구성 중 로그인 화면을 만나면 질문 카드로 |
| 5 Agent | 감지된 Agent를 자동 연결(UX1 U2). 없을 때만 보임 | |
| 6 프로젝트 정보(원본) | 유지하되 "나중에" 버튼으로 건너뛸 수 있음 | Init 질문 카드, 원본 추가 제안 |
| 7 자동화 정책 (Agent 권한·자동 수리·금지 동작·예산) | **삭제**. 기본값 적용 (4절) | 권한 때문에 막힐 때 제안 카드, 설정 화면 |
| 8 기록 | **삭제**. 기본값 적용 | 설정 화면 |
| 9 완료 | "Init 시작"으로 바로 이어짐. "처음 할 일"은 녹화가 아니라 Agent에게 맡기는 쪽으로 | |

결과: 보통은 **프로젝트 → 게임 → (원본, 건너뛰기 가능) → Init 시작** 3~4화면이다.

## 4. 없앤 단계의 기본값

- **자동화 정책**
  - 지금 기본 프리셋("그래프 작성")을 그대로 쓴다.
  - 자동 수리, 예산 분·실행 수도 지금 기본값을 쓴다.
- **금지 동작**
  - 기본은 빈 목록이다. 개발 환경에는 보통 막을 동작이 없다.
  - 필요하면 설정 도우미에서 더한다.
- **기록**: 지금 기본값(통과·실패 보관 일, 영상 정책)을 쓴다.
- **테스트 계정**: 없음. 처음 필요할 때 묻는다.
- **Agent 권한 중 개발 환경마다 없을 수 있는 것**(빌더 사용 등): 묻지 않는다. Agent가 필요하다고 판단하면 설정 바꾸기 제안으로 올린다.

## 5. Init 범위

Init이 하는 것
1. **QA 위키 기본 뼈대**
   - `wiki/overview.md`, `glossary.md`, `environment.md`를 쓴다.
   - 원본이 있으면 원본에서, 없으면 화면에서 추측해 쓴다.
2. **게임 요소 러프 파악**
   - 기능 목록과 기능별 한 줄 설명을 쓴다.
   - 기능 지도(기능 → 화면 → 주장 후보) 깊은 탐색은 하지 않는다.
3. **게임 실행·종료**
   - 실행 → 창 잡기 → 첫 화면 캡처 → 종료를 확인한다.
   - 결과물로 `게임 실행`·`게임 종료` 서브그래프를 만든다. 이후 모든 테스트가 이 둘을 부른다.
4. **먼저 직접 알아보고, 막힌 것만 묻는다**
   - 직접 알아내는 것들 (묻지 않는다)
     - 런처·패치 창의 진행 버튼: 화면을 보고 눌러 본다.
     - 여러 창 중 게임 창: 창 목록과 화면으로 고른다.
     - 종료 방법: 메뉴로 나가기 → 창 닫기 → 프로세스 끝내기 순으로 시도한다. 된 방법을 `게임 종료` 서브그래프에 쓴다.
     - 실행 인자·서버 설정: 읽기 허용 폴더의 bat·설정 파일을 읽는다.
     - 장르·핵심 플레이: 원본이나 화면을 보고 추측해서 쓴다.
   - **Init은 질문을 만들지 않는다.** 게임을 알아 가는 것은 이후 Agent가 직접 플레이하며 화면 지도를 그리면서 한다.
   - 궁금한 것은 위키 "모르는 것"에 남긴다. 이후 탐색에서 Agent가 직접 확인한다.
   - 실행·종료 자체가 막히면 질문 대신 **막힘 보고**로 끝낸다(사건 `needs_info`).
     - 보고에는 시도한 것과 결과를 적는다.
     - 예: "실행하면 '서버에 연결할 수 없음'이 떠요. 읽기 허용 폴더의 설정 파일 두 개를 확인했지만 주소가 없었어요."
     - 사람이 설정을 고친 뒤 "이어서 진행"을 누르면 다시 이어 간다.
   - 계정은 접속 경로 단계에서 묻는다(그 단계의 유일한 질문).

Init이 하지 않는 것 (다음 단계로)
- 로그인, 서버 선택, 캐릭터 선택처럼 게임 안으로 들어가는 경로
- 기능별 화면 탐색, 주장 후보 대량 생성

## 6. 다음 단계: 접속 경로 만들기

- Init 보고 끝에 "다음: 게임 접속 경로 만들기" 카드를 보인다. 사람이 눌러서 시작한다.
  - 자동으로 이어 가지 않는다. 사용자가 결과를 보고 고를 시간을 준다.
- 하는 일
  - 실행부터 로비(또는 첫 플레이 가능 화면)까지 가는 `접속` 서브그래프를 만든다.
  - 그 과정의 화면을 화면 지도에 올린다.
- 로그인 화면을 만나면 그때 계정을 묻는다.
  - 일반 질문의 글 답으로 받지 않는다. 글 답은 팀 지식에 남기 때문이다.
  - 질문 카드에 "테스트 계정 등록" 단추를 두고, 지금 계정 단계의 비밀값 입력(`secrets.create`)을 연다.
  - Agent는 비밀값 이름(`$secret`)만 쓴다.
- 끝나면 "다음: 기능 테스트 만들기"를 제안한다. 지금의 followup·author 흐름이다.

## 7. 정해진 것

- 사용자 결정 (2026-11-12~13)
  - 계정 단계와 Agent 권한 단계를 없앤다.
  - Init은 기본만 하고, 접속 구성은 다음 단계에서 한다.
  - 금지 동작 기본값은 빈 목록이다.
  - Init이 `게임 실행`·`게임 종료` 서브그래프를 만든다.
  - Init은 질문을 만들지 않는다. 막히면 막힘 보고로 끝낸다(처음 정한 "질문 3개"를 바꿈).
- 추천안으로 진행 중 (사용자가 아니라고 하면 바꾼다)
  - 기록 단계도 없앤다.
  - 접속 경로 구성은 사람이 눌러서 시작한다.
- 마법사에서 뺀 설정(계정·자동화 정책·기록)은 설정 도우미에서 언제든 연다.
