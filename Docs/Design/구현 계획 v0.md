## 1. 마일스톤

각 단계는 **혼자서 돌아가는 결과물**로 끝난다. 완료 기준을 통과해야 다음으로 간다. 실제 게임 검증은 마지막까지 기다리지 않고 M1부터 레포 밖에서 계속한다.

| 단계 | 만드는 것 | 완료 기준 |
|---|---|---|
| **M0a 실행 의미** | 모노레포, CI(라이선스 검사 포함), 메타스키마, 그래프 로더·실행 전 검증, 실행 의미(판정·반복·순수 노드·`$link`·재시도), 흐름·값·판정 노드. 한 프로세스 안에서 가짜 캡처·입력으로 실행 | 판정 순서표 전체, "반복 안에서 변수를 바꾸면 다음 조건이 달라짐", "지난 반복 출력 참조 거부", "중첩 반복에서 올바른 done 진입", 재시도 시도 기록, 스키마 문서 예시 JSON 검증 통과 |
| **M0b 프로세스·기록** | runner 프로세스, 워커 프로토콜(최소), 감독자, 취소 순서, 입력 임대권, 권한 엔진, 기록 정책 API, `events.jsonl`(seq)·스냅샷, CLI `kookabug run` | 노드 실행 중 취소·멈춤 요청이 들어감. 워커를 죽여도 기록이 확정됨. runner를 강제 종료해도 감독자가 기록을 마무리하고 눌린 키를 해제. 잘린 JSONL을 읽어 "중단"으로 표시. 같은 행위가 CLI·daemon에서 같은 권한 판정 |
| **M1 비전·입력·배포** | WGC 캡처, SendInput, DPI, 이미지 매칭, OCR(RapidOCR), target 파일, 앱·창·이미지·OCR·입력 노드, 예제 게임, 최소 `*.screen.json`, `kookabug target test`(매칭 미리보기 이미지), 설치 파일 빌드 | 예제 게임에서 `enter_world` + `inventory_open` 통과, 일부러 깨뜨리면 실패 위치·스크린샷이 남음. **Python이 없는 깨끗한 Windows**에서 설치 → CLI·캡처·OCR 실행. 실제 GPU 게임 하나(레포 밖)에서 DPI 100/150/200%, 창 이동·크기 변경, 포커스 잃음, 전체화면 전환, 한글 입력 확인. 지원하지 않는 조건은 정확한 사유로 끝남 |

| **M3 기록·디버거** | 기록 뷰어(타임라인·스크린샷·서브그래프 펼치기·지난 성공과 비교), 브레이크포인트·Step Into/Over, 재개 시 재검증, 실패 시 영상 보관(`video: failed_only`) | 실패 실행을 뷰어로 열어 실패 노드까지 한 번에 이동. 재개 후 대상이 사라졌으면 입력이 나가지 않음. 오래된 OCR로 분기하지 않음. 멈춘 시간이 두 타임아웃에서 빠짐. 성공한 실행의 영상은 지워지고, 기록 끈 구간은 영상에도 없음 |
| **M4 녹화** | 녹화기(사람 입력 → 노드), target 편집기 확장 | 예제 게임 로그인을 녹화한 그래프가 바로 재생 통과. 클릭 **이전** 프레임으로 target을 만든다. 툴 자신이 보낸 합성 입력은 녹화하지 않는다. 비밀번호 칸 입력은 글자 그대로 저장하지 않고 `$secret` 참조로 바꾸라고 요구한다 |
| **M5 Agent** | Kookabug MCP 서버(툴셋·연결별 상태), 에이전트 패널(ACP), Agent 판단 노드 2종 | 외부 에이전트가 MCP로 그래프를 만들고 실행하고 실패를 분석. 권한 거부가 집행됨. UI와 에이전트가 동시에 고치면 늦은 쪽이 거부됨. 판단 노드의 에이전트에는 제어 도구가 주어지지 않음 |
| **M6 플러그인** | 설치, 잠금(해결된 의존성 환경까지), 공유/격리 venv, SDK 배포, UI 확장(JS) | 외부 레포의 샘플 플러그인이 설치·실행됨. 의존성이 충돌하는 두 플러그인이 격리됨. 설치 실패가 기존 환경을 깨지 않음. 다른 PC에서 잠금 파일로 같은 환경이 재현됨 |
| **M7 화면 지도** | 화면 지도 뷰어, Agent 탐색 결과 저장(`screens/_explored/`) | 예제 게임 탐색 결과가 화면 카드와 이동 그래프로 보이고, 사람이 확인해 `screens/`로 옮길 수 있음 |
| **MVP 검증** | 실제 게임 프로젝트에서 사용 (레포 밖) | 실제 게임의 스모크 테스트 몇 개를 무인으로 매일 돌림 |

- **예제 게임**: 레포 안에 작은 가짜 게임(`fixtures/sample-game`)을 둔다. 타이틀 → 로그인 → (점검 팝업) → 로비 → 월드 → 인벤토리. 실행 옵션으로 점검·로그인 실패·느린 로딩·해상도를 바꾼다. CI E2E와 문서 예시가 모두 이 게임을 쓴다
- **실제 GPU 게임 검증**은 레포 밖에서 한다 (회사 게임 내용을 레포에 넣지 않는 원칙). 공개 검증용으로는 오픈소스 게임(예: SuperTuxKart)을 설치해 대상으로만 쓰고 레포에 넣지 않는다

## 2. 레포 구조

```
kookabug/
├─ apps/desktop/              Electron + React (TypeScript)
├─ packages/schema/           메타스키마: graph, target, workspace, events, node-schema, RPC 메시지
├─ packages/ui-sdk/           UI 확장 플러그인용 TS API (MIT)
├─ python/
│  ├─ kookabug_core/          그래프 로더·의미 검증, 러너, 판정, 이벤트 기록, 스냅샷, 권한 엔진, 입력 임대권, 감독자
│  ├─ kookabug_daemon/        워크스페이스 서비스 (UI·MCP가 붙는 곳)
│  ├─ kookabug_nodes/         코어 노드 (SDK로 작성)
│  ├─ kookabug_platform/      Windows 캡처·입력·창·DPI·OCR 백엔드
│  ├─ kookabug_mcp/           MCP 서버 (stdio shim)
│  ├─ kookabug_cli/           `kookabug` 명령
│  └─ kookabug_sdk/           노드 SDK (MIT, 별도 LICENSE)
├─ fixtures/sample-game/      예제 게임
├─ docs/                      사용자 문서
└─ LICENSE                    Apache-2.0
```

- **메타스키마**(`packages/schema`)는 파일과 통신 형식의 단일 출처다. 여기서 pydantic v2 모델과 TS 타입을 생성한다
- **노드 정의**는 메타스키마가 아니라 Python SDK 선언에서 생성한다 (`kookabug-sdk build`)
- 생성된 타입은 모양만 검사한다. 동적 출구, 링크 유효성, 호출 경로, 반복 범위 같은 **의미 검증은 Python 코어**가 최종 책임진다. 에디터는 코어의 검증 결과를 받아 표시한다
- 코어 노드도 `kookabug_sdk`로 작성한다

## 3. 프로세스와 통신

```
Electron UI ──WebSocket JSON-RPC──┐
                                  ├── kookabug daemon (워크스페이스당 1개)
에이전트 CLI ──stdio MCP── kookabug mcp ──┘      │ 인덱스, 검증, 실행 관리, events 구독·재전송
                                                 │ (= 감독자)
                                                 └─named pipe── runner (실행당 1개, Job Object)
                                                                 └─named pipe── plugin worker (실행에 귀속)
```

| 구간 | 방식 |
|---|---|
| UI ↔ daemon | 로컬 WebSocket(127.0.0.1) + JSON-RPC 2.0. 접속 정보는 `.kookabug/session.json` |
| 에이전트 ↔ MCP | 에이전트가 `kookabug mcp`(stdio)를 띄우고, 이것이 daemon에 붙는다 |
| daemon ↔ runner, runner ↔ worker | **named pipe** + 길이 접두 JSON-RPC. stdout·stderr는 프로토콜에 쓰지 않고 로그로만 받는다 (플러그인의 `print()`가 통신을 깨지 않게) |
| 큰 데이터 | 캡처 프레임은 수명이 관리되는 공유 메모리 참조로 넘긴다. 파일은 기록용 artifacts만 |
| CLI 단독 | `kookabug run`은 daemon 없이 runner를 직접 띄우고 **CLI 프로세스가 감독자**다 |

### 계약

- **수명**: UI를 꺼도 daemon과 실행은 유지된다. daemon이 죽으면 runner는 부모가 사라진 것을 감지하고 스스로 취소 절차를 밟는다. daemon 재시작 후 실행을 이어받는 것은 MVP에서 하지 않는다
- **`session.json`**: PID, 시작 ID, 프로토콜 버전, 포트, 토큰. 이미 있는데 PID가 죽었거나 시작 ID가 다르면 오래된 파일로 보고 새로 만든다. 동시에 두 daemon이 만들려 하면 파일 잠금으로 하나만 이긴다
- **권한·입력 임대권·감독 코드는 `kookabug_core`에 하나만** 있고, daemon과 CLI가 같은 코드를 쓴다. 사람이 없는 실행에서 `ask`는 거부로 처리한다. 권한 판정 대상은 에이전트이고(사람의 직접 사용은 판정하지 않음), 정책은 사용자 설정·`.kookabug/local.json`·`kookabug.json`(팀 상한) 세 계층이다 ([[워크스페이스 구조]] "에이전트 권한"). 권한 설정 파일이 잘못되면 에이전트 요청은 전부 거부, `ask`는 승인 전에 실행하지 않는다. 판정은 공유 서비스(`WorkspaceService.authorize`) 하나가 한다
- **노드 실행과 통신 수신은 다른 스레드**다. 동기 노드가 돌고 있어도 취소·멈춤 요청을 받는다. 워커 ↔ runner는 양방향이다 (워커의 `ctx.capture()`가 runner로 요청을 보내는 동안에도 runner가 취소를 보낼 수 있다)
- **기록 작성자는 runner 하나**다. 이벤트마다 `seq`를 붙여 `events.jsonl`에 쓰고, daemon은 파일을 구독해 UI에 다시 보낸다. UI가 느리거나 끊겨도 runner는 멈추지 않는다. UI는 다시 붙을 때 마지막 `seq` 이후를 요청한다. runner가 죽은 실행은 프로세스 종료를 확인한 뒤 감독자가 마무리 기록을 쓴다
- **프로세스 정리**: 실행마다 Windows Job Object를 만들어 우리가 띄운 runner·worker·보조 프로세스를 넣는다. `core.app.launch`로 띄운 게임은 넣되, `core.window.attach`로 붙은(사용자가 미리 띄운) 게임은 넣지 않는다. Job 종료가 키 해제를 대신하지는 않는다
  - Job 수명: 감독자가 이름 있는 Job(`Local\Kookabug.Run.<run_id>`)을 "마지막 핸들이 닫히면 안의 프로세스를 끝냄"(`KILL_ON_JOB_CLOSE`)으로 만들고, runner는 시작하자마자(어떤 자식도 띄우기 전에) 그 Job을 이름으로 열어 자기를 넣는다. 그래서 핸들이 둘이고, **둘 다 닫혀야** OS가 Job을 정리한다. 감독자만 죽으면 runner가 취소 순서를 밟고 끝나며 runner의 핸들이 마지막으로 닫혀 남은 워커가 끝난다. runner만 죽으면 감독자가 마무리한 뒤 Job을 끝낸다. 둘 다 죽으면 OS가 정리한다
  - Job 핸들은 상속하지 않고 다른 프로세스에 넘기지 않는다. runner 뒤에 띄운 워커는 생성 시점부터 Job 소속이라 "띄운 뒤 넣기" 사이의 경쟁이 없다
- **워커**: venv는 재사용하지만 워커 프로세스는 실행마다 새로 띄운다. 실행 중에는 플러그인 설치로 그 환경을 바꾸지 않는다

### 취소 순서

1. 입력 차단 (새 입력 요청 거부)
2. 이번 실행이 누른 키·마우스 버튼 해제
3. 워커에 취소 요청 → 기한 안에 응답 없으면 워커 종료
4. 기록 확정 (`step.end` 중단 표시, 실행 결과)
5. runner 종료

runner가 이 순서를 못 밟고 죽으면 감독자가 2·4를 대신한다. 감독자가 키를 해제하려면 runner가 "지금 누르고 있는 키"를 이벤트로 남겨야 한다 (`input.down` / `input.up`).

### 입력 임대권

- 하나의 Windows 사용자 세션에서 **입력을 보낼 수 있는 주체는 하나**다: 실행 / 녹화 / MCP 직접 제어 중 하나
- Windows 이름 있는 뮤텍스(`Local\Kookabug.InputLease`)로 구현한다. 소유 프로세스가 죽으면 OS가 풀어 준다. 소유자 정보(종류, 워크스페이스, 실행 ID)는 옆 파일에 적는다
- MVP는 이미 다른 주체가 갖고 있으면 **명시적으로 거부**하고 누가 갖고 있는지 알려 준다. 대기·양보는 이후 버전
- 디버거로 멈춘 실행도 임대권을 유지한다. 그동안 Agent가 직접 클릭하려면 실행을 끝내야 한다

### MCP

- 활성 툴셋은 **에이전트 연결별** 상태다
- `kb_graph_patch`는 기준 revision을 받는다. 그 사이 UI나 다른 연결이 고쳤으면 거부한다
- `kb_run_start`는 중복 방지 키를 받는다. 연결이 재시도해도 실행이 두 개 생기지 않는다

## 4. 배포

- Windows 설치 파일: electron-builder v26(NSIS) + electron-updater + GitHub Releases
- Python 런타임은 **앱에 포함**한다 (python-build-standalone + 코어 의존성 미리 설치). 플러그인 의존성 설치용 uv도 포함한다
- CLI만 쓰는 CI용으로 PyPI 배포 (`pip install kookabug`)
- **라이선스 감사는 M0부터 CI**에서 한다: Python 의존성(pip-licenses), JS 의존성, python-build-standalone 배포물에 들어 있는 라이선스 메타데이터, OCR 모델·사전 파일. 결과를 설치 파일의 `THIRD_PARTY_NOTICES`로 묶는다
- 코드 서명: SignPath(오픈소스용) 신청. 자동 승인되지 않고, 남이 만든 바이너리(Python, uv)를 재서명하는 데 제약이 있으므로 서명 범위를 신청 때 확인한다. 서명 전까지는 SmartScreen 경고를 문서로 안내한다
- M1 완료 기준에 "Python 없는 깨끗한 Windows에서 설치·실행"이 들어 있다. 배포는 마지막에 붙이는 일이 아니다

## 5. 캡처·입력·비전

| 영역 | 결정 |
|---|---|
| 캡처 | **WGC**(창 단위)를 먼저 완성한다. DXGI는 검증된 뒤 **명시적으로 고르는** 선택 경로로 추가한다. 검은 프레임만 보고 백엔드를 자동으로 바꾸지 않는다 (검은 로딩 화면은 정상일 수 있고, DXGI는 모니터 단위라 위에 겹친 다른 창을 찍는다). 백엔드 선택은 사전 기능 검사와 명시적 API 오류로만. PrintWindow·BitBlt 자동 폴백은 이후 버전 |
| 프레임 정보 | 프레임마다 백엔드, 대상 창, 캡처 영역, 좌표 변환, 시각을 붙인다. 백엔드가 바뀌면 기존 관측값은 무효 |
| 입력 | SendInput. 입력 직전 포그라운드·창 유효성 확인. 게임이 관리자 권한이면 러너도 관리자 권한 필요 (검사 후 안내) |
| DPI | runner 시작 때 Per-Monitor V2. 캡처·입력을 클라이언트 영역 물리 픽셀로 통일 |
| 이미지 매칭 | OpenCV `matchTemplate`(TM_CCOEFF_NORMED) + 멀티스케일 + 색 확인 |
| OCR | 엔진 교체 가능. **기본 RapidOCR**(ONNX Runtime CPU). 모델·사전·설정 파일과 해시를 배포에 포함한다. **Windows OCR은 선택 백엔드**: Microsoft가 데스크톱에서 패키지 ID를 요구하므로, 지원 조건을 확인한 환경에서만 켠다. Tesseract는 넣지 않는다. 한국어 모델의 정확도·속도는 M1에서 예제 게임과 실제 게임 폰트로 측정한다 |
| OCR 신뢰도 | 엔진마다 척도가 다르다. 노드 출력 `confidence`는 엔진이 주지 않으면 `null`이고 (Windows OCR은 주지 않음), 엔진 사이에 같은 척도로 비교하지 않는다 |

| 라이브러리 | 라이선스 | 비고 |
|---|---|---|
| `windows-capture` | MIT | WGC·DXGI 경로가 모두 있다. **dxcam은 넣지 않는다** (같은 경로를 이 라이브러리로 쓸 수 있음). HWND 지정·크기 변경·종료·최소화·장시간 안정성은 M1에서 검증 |
| `opencv-python-headless` | Apache-2.0 (wheel 동봉 라이브러리는 감사로 확인) | |
| RapidOCR + `onnxruntime` | Apache-2.0 / MIT | Windows에서 VC++ 런타임 필요 → 설치 파일에 포함 |
| `winrt-Windows.Media.Ocr` | MIT | 선택 백엔드용 |
| ctypes (표준 라이브러리) | PSF 계열 | Job Object·뮤텍스·프로세스 식별(PID + 생성 시각)을 Win32 API로 직접 부른다. pywin32는 넣지 않는다 (동봉 DLL·라이선스 감사 부담). 창 API도 M1에서 같은 기준으로 고른다 |

## 6. 기록 정책 구현

| 단계 | 구현 |
|---|---|
| M0b | 기록 API 하나로 모든 스크린샷·영상·OCR 텍스트를 저장한다. 노드가 파일을 직접 쓰지 않는다. secret 입력 노드 자동 생략, 상위 off 우선, 생략 이유 기록. 예외 시 스크린샷(SDK)도 이 API를 거친다 |

## 7. MCP 도구

core 툴셋만 항상 켜고, 나머지는 `kb_toolset_enable`로 켠다.

| 툴셋 | 도구 |
|---|---|
| core | `kb_project_info`, `kb_toolset_enable`, `kb_graph_list`, `kb_graph_get`, `kb_graph_validate`, `kb_node_search`, `kb_run_status`, `kb_log_search` |
| graph_edit | `kb_graph_create`, `kb_graph_patch`(노드 추가·수정·삭제·연결 연산 묶음, 기준 revision 필수), `kb_target_create`(스크린샷에서 자르기) |
| run | `kb_run_start`(중복 방지 키), `kb_run_cancel`, `kb_run_events`, `kb_run_artifact_get` |
| observe | `kb_screen_capture`, `kb_image_find`, `kb_ocr_read` |
| control | `kb_input_click`, `kb_input_key`, `kb_input_type`, `kb_app_launch` (입력 임대권 필요) |
| screens | `kb_screen_list`, `kb_screen_get`, `kb_screen_save` |

**권한 프리셋** (기본 `graph_author`). 조회 도구 = 읽기만 하는 도구. 판정 순서는 [[워크스페이스 구조]] "에이전트 권한"

| 도구 | `read_only` | `graph_author` | `runner` | `full` |
|---|---|---|---|---|
| core 전체 (조회) | allow | allow | allow | allow |
| graph_edit 전체 (변경) | deny | ask | ask | allow |
| `kb_run_start`, `kb_run_cancel` (변경) | deny | deny | allow | allow |
| `kb_run_events`, `kb_run_artifact_get` (조회) | allow | allow | allow | allow |
| observe 전체 (조회) | allow | allow | allow | allow |
| control 전체 (변경) | deny | deny | ask | allow |
| `kb_screen_list`, `kb_screen_get` (조회) | allow | allow | allow | allow |
| `kb_screen_save` (변경) | deny | ask | ask | allow |

툴셋 값(`allow`·`ask`·`deny`)을 주면 그 툴셋의 변경 도구에 그 값을, 조회 도구에는 `deny`일 때만 `deny`를 쓴다.

- 서브그래프를 도구로 노출할 때는 안쪽 노드가 쓰는 권한을 합쳐서 검사한다
- `kb_graph_patch`는 노드 ID를 바꾸는 연산을 받지 않는다
- **Agent 판단 노드**(`cli_judge`, `api_judge`)가 부르는 에이전트에는 Kookabug 제어 도구를 주지 않는다. 이미지와 질문만 준다. 에이전트 패널의 Agent와 실행 환경을 분리한다

| M2 완료 기준을 "무수정 저장 바이트 동일 + 의미·ID 보존"으로 | 무작위 ID·좌표 때문에 "손으로 쓴 파일과 diff 없음"은 성립하지 않는다 |
| 최소 target 편집기를 M2로 당김 | M4까지 미루면 그동안 임계값·검색 영역을 손으로 고친다 |
| 권한 엔진을 M0b로 | CLI·UI·MCP의 같은 행위가 같은 판정을 받아야 한다 |
| 판단 노드에 제어 도구 주지 않음 | "판단만"이라는 MVP 범위를 지킨다 |
| M6에서 화면 지도를 M7로 분리, 잠금에 해결된 의존성 환경 포함 | 검증 단위가 다르다. 플러그인 버전·해시만으로는 전이 의존성이 재현되지 않는다 |

| 기록 작성자 runner 하나 + `seq` | UI가 느려도 runner가 멈추지 않고, 다시 붙을 때 빠진 구간을 받는다 |
| Job Object, 워커는 실행에 귀속 | 프로세스 트리 정리. 공유 venv와 공유 워커 프로세스는 다르다 |

| 메타스키마 단일 출처 범위 축소 | 노드 정의는 Python SDK에서 생성하고, 의미 검증은 Python 코어가 책임진다 |

| 영상 `failed_only` 구현 방식 명시 (M3) | 실패한 뒤에 녹화를 시작할 수는 없다. 임시 기록 → 성공 시 삭제 |
| OCR `confidence`는 없으면 `null` | Windows OCR은 신뢰도를 주지 않고, 엔진마다 척도가 다르다 |

### M0b 구현 반영

| 바뀐 것 | 이유 |
|---|---|
| 권한: 판정 대상은 에이전트, 정책 세 계층(사용자 설정·`local.json`·`kookabug.json` 팀 상한), 7장 "기본 권한" 열을 프리셋 4개 표로 바꿈(기본 `graph_author`는 `kb_run_start`가 deny), 잘못된 권한 설정은 에이전트 거부 (3장 계약, 7장) | 툴셋 하나에 값 하나로는 "편집은 묻고 실행은 막는다" 같은 조합과 팀이 정한 한도를 표현하지 못한다. 사람이 쓰는 CLI까지 막으면 권한 설정 실수로 사람이 아무것도 못 한다. 권한 파일이 틀렸을 때 기본값으로 돌아가면 팀이 막은 것이 조용히 풀린다 |
| Job Object·뮤텍스를 pywin32 대신 ctypes로 (5장 표), 실행 Job은 감독자가 만들고 runner가 이름으로 열어 자기를 넣는 두 핸들 (3장 "프로세스 정리") | 런타임 의존성·라이선스 감사 항목이 늘지 않는다. 감독자 핸들 하나뿐이면 감독자가 죽는 순간 runner까지 끝나 키 해제·기록 마무리를 할 주체가 없다 |
