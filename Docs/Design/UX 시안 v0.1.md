## 디자인 방향

- **앱 틀은 VSCode 방식**
  - 타이틀 바(가운데 명령 검색 Ctrl+P), 액티비티 바, 사이드바(섹션별 접기), 에디터 탭 + 경로 표시줄, 하단 패널 탭, 상태 바
  - 차분한 회색 다크 톤에 강조색은 파랑 하나. 모서리는 각지게, 글자는 촘촘하게
  - 상태 바 색으로 지금 상태를 표시: 실행 중 파랑 / 녹화 중 빨강 / Agent 탐색 중 보라 / 대기 중 회색
- **우측 에이전트 패널은 Aside 방식**
  - 세션 제목 + 새 대화 버튼
  - 내 메시지는 오른쪽 말풍선, 에이전트 답변은 말풍선 없는 본문
  - 도구 호출은 "작업 9초 · 도구 2개 ›"처럼 한 줄로 접고, 진행 중이면 펼쳐서 표시
  - 승인 요청은 카드로 표시: 한 번 허용 / 항상 허용 / 거부
  - 입력창: 둥근 상자 + 첨부 버튼 + @첨부 칩 + 원형 보내기·중지 버튼. 아래 줄에 에이전트 이름, 권한 프리셋, MCP 상태
- VSCode 기본 다크 테마와 분위기만 비슷하게 맞추고, 그대로 복제하지 않는다
- 예시 게임은 가상의 "SampleRPG"

## 첫 실행 흐름

새 프로젝트를 만들 때는 설정 화면이 먼저 나오고, 끝나면 노드 에디터(1번 화면)가 열린다. 레이아웃은 Aside 온보딩을 참고했다: 왼쪽에 설명과 입력, 오른쪽에 그림, 아래에 이전 · 진행 점 · 다음(↵). 색은 툴과 같은 어두운 톤. 캔버스에서 Play로 이전·다음을 눌러 넘겨 볼 수 있다.

M2 에디터(앱 틀·시작 화면)를 만들며 시안과 다르게 정한 것. 색은 시안에서 뽑은 역할 토큰(`apps/desktop/src/renderer/theme/tokens.css`)이고, 시안 대비 확인은 자동 검사(역할 색·치수·글꼴)와 나란히 비교 PNG로 한다.

| 1 노드 에디터 | **파일 보기 탭**(시안에 없음): 전용 편집기가 없는 탐색기 파일(화면 지도, `kookabug.json`·`kookabug.lock`, 그 밖 JSON·`.md`·`.txt`, PNG 등 이미지)을 누르면 읽기 전용 탭이 열린다. 탭 글자 SCREEN·JSON·MD·TEXT·IMAGE(설정 파일 글자 색), 머리 줄 "읽기 전용"·크기. JSON은 원문 낱말 그대로 두 칸 들여쓰기·구문 색(키·문자열·숫자·리터럴), 그 밖은 원문, 이미지는 그림과 크기. 밖에서 바뀌면 다시 읽고, 지워지면 "파일이 없어요". 그래프·`.target.json`은 지금처럼 캔버스·TARGET 탭이다. 고치기는 아직 없다. 탐색기에 보이는 범위(`tests/`·`subgraphs/`·`targets/`·`screens/`·루트 설정 파일, `runs/`·`.kookabug/`는 이름만)는 그대로 | 2026-11-03 사용자 요청 ⑨ |
| 기록 뷰어 | **오류 스텝의 이유**: 증거 머리 그래프 이름 뒤에 `error` 스텝은 `step.end.error`의 `code: message`, 그 밖에는 스텝 메시지 (2026-11-03 사용자 보고) | 에디터 실행 결과(노드 결과 패널)와 같은 규칙. 오류 이유는 색인 메시지에 없어 머리가 비어 있었다 |
